## 一、问题定位

### 1.1 现有方法的盲区

流量 = 周期项 + 趋势项 + 异常项

- 周期项/趋势项：DRL、传统优化的主场，时序模型能处理
- 异常项：语义信号驱动的突发需求（演唱会、灾害、赛事），传统方法看不见

**你的方法专攻异常项**——不和传统方法抢周期性流量，只做它们抓不住的部分。

### 1.2 现有精确方法的规模瓶颈

单星MILP（Zamacola 2026）：
- 三自由度联合优化（illumination + power + bandwidth）
- time-split解决了时间维度的复杂度爆炸
- 但用户维度的复杂度爆炸没有解决：7用户80小时，星座级直接死机

**核心gap**：星座级没有精确优化工具，现有方案全是启发式/DRL，没有optimality gap保证。

## 二、核心框架

### 2.1 两级分解（解决规模问题）

**类比time-split**：
- time-split沿时间轴分解 → 压住时间维度复杂度
- 多星agent沿空间轴分解 → 压住用户维度复杂度

两个分解叠加，把星座级精确优化从不可行变成工程上可用。

**分组方式：按轨道面静态划分**
- 组成员永远不变，不存在飞进飞出的重组问题
- 边界关系由轨道参数决定，可提前预计算
- 与Starlink实际架构对齐

### 2.2 三层架构

```
[语义规划层]  分钟级
    LLM读语义信号，预判需求，期货式预锁资源
    RAG检索历史相似场景，复用历史决策
    输出：各组资源配额 + 优先级权重
        ↓
[组间协商层]  分钟级
    资源竞争裁决：按优先级分配功率配额
    频率干扰处理：低优先级组调整边界cell的bin
    L-HTN约束：物理约束编码进HTN，LLM输出不违反硬约束
    输出：各组功率配额 + 边界频率方案
        ↓
[组内执行层]  秒级/毫秒级
    单星time-split MILP精确求解
    在配额约束 + 边界频率约束下联合优化
    实时随机波动由传统优化兜底
    输出：每时隙的照射/功率/带宽分配方案
```

### 2.3 时间尺度分离

```
语义规划层   分钟级    LLM推理（10-30秒），不在实时回路
组内优化层   秒级      MILP Tool调用
执行层       毫秒级    传统优化处理实时波动
```

LLM不在实时回路里，慢不影响系统实时性。

## 三、关键技术设计

### 3.1 决策缓存复用（解决实时性）

借鉴SAIL论文的Archive检索机制：

```
新场景到来
    ↓
RAG检索历史相似场景
    ↓
相似度>0.9  → 直接复用历史决策，跳过MILP（毫秒级）
相似度中等  → 历史解作为warm start喂给Gurobi
             + LLM预测变量初始值辅助
             → MILP从好起点收敛，速度大幅提升
相似度低    → LLM预测变量初始值作为warm start
             → 完整MILP求解，但起点比随机好
```

**核心贡献点**：语义感知的warm start替换数值驱动的warm start（论文里用DB方法），在有语义信号的场景下显著加速MILP求解。

**缓存质量控制**（对应SAIL的局限性）：
- 设质量门槛，只缓存高质量决策（UC < 阈值 + TTS < 阈值）
- 定期清理低质量缓存，地面站统一维护

### 3.2 优先级裁决机制（解决资源竞争）

```
优先级 = α × UC欠债归一化值 + β × LLM语义权重
```

- UC欠债：从MILP的γ变量直接读，纯数值
- LLM语义权重：RAG+LLM判断覆盖区域的事件驱动需求

资源竞争：按优先级从高到低分配功率配额，超出PT截断
频率干扰：低优先级组调整边界cell的bin，组内局部重排（只涉及边界附近cell，不全组重算）

### 3.3 不确定性追踪（核心创新点）

三类不确定性，性质不同：

**推理不确定性**：LLM自身输出置信度，用normalized entropy，复用SAUP方法

**检索不确定性**：RAG返回场景与当前场景的相关性
- 多维度相似度加权（地理/规模/时间/场地）
- 进阶：用历史(相似度, 误差)样本对构造条件误差分布P(ε|s)，输出置信区间（Conformal Prediction）

**工具不确定性**：MILP返回结果与LLM预期的偏差，SAUP未覆盖，是真实增量

三级响应：
```
高置信  → 自动决策
中置信  → 触发意图澄清模块
低置信  → 升级人工，附不确定性来源定位报告
```

人工介入率目标：< 5%

### 3.4 约束保障机制（解决LLM输出违反物理约束）

三层防护（基于L-HTN框架）：

```
第一层：HTN约束
    物理硬约束编码进HTN（PT上限、bin数量N、照射数Nill）
    单个Agent输出生成过程中不违反本组硬约束

第二层：组间冲突裁决
    中心协调器汇总各组申请
    检查加总是否超过全局PT
    超了按优先级截断

第三层：MILP可行性验证
    协商结果下发组内MILP前验证边界约束可行性
    不可行退回重协商
```

### 3.5 期货预锁机制（解决提前配置）

借鉴MILP论文的UC carry-over结构（式23-24）：

UC carry-over是"记past欠账"（被动向后看）
期货预锁是"占future额度"（主动向前看）

数学结构对称，直接用carry-over的线性约束模板，方向反过来即可。

预测时间窗口N：敏感性分析（N=5/10/15/30分钟各跑一遍），取最优值。

## 四、与现有方法的关系

```
随机流量波动（周期项）   → 传统优化/DRL处理
语义驱动突发需求（异常项）→ LLM+RAG处理（你的主场）
```

**MILP论文给你三样东西**：
- 工具：组内精确求解器，直接复用
- 基准：组内MILP结果是性能上界，量化optimality gap
- 理论类比：time-split证明了弱耦合分解的可行性，你的空间分解数学结构同构

**SAIL论文给你**：
- 决策缓存复用机制（Archive检索）
- 策略蒸馏路线（执行时间从644秒→72秒）

**L-HTN论文给你**：
- 约束保障的第一层（HTN约束LLM输出）
- 预生成场景数据库思路（离线预计算，在线查表）

**Shachi框架给你**：
- 多Agent形式化（Config/Memory/Tools/观测/动作）
- 动态成员变化处理（更新观测，不重建Agent）
- 组间通信由环境中介，格式标准化

## 五、风险与控制

### 风险一：组间最优性损失不可控

**来源**：组间耦合是双向的（干扰+资源竞争），比time-split的单向carry-over复杂

**控制**：
- 按轨道面划分，最小化边界cell数量，从源头减弱耦合
- 频率冲突只需边界cell局部重排bin，影响范围小
- 拉格朗日松弛给出理论对偶gap bound
- 消融实验量化组间协商引入的最优性损失

**兜底**：损失大的场景作为分析发现，给出"耦合强度阈值"经验规律

### 风险二：LLM输出违反物理约束

**控制**：三层防护（HTN约束 + 组间裁决 + MILP可行性验证）

### 风险三：组划分静态vs动态

**控制**：
- 按轨道面静态划分，组成员永远不变
- 每规划周期重新协商，适应覆盖区域变化
- 两级协商架构（轨道面小组内部先协商，再跨组协商），Agent数量从72压到20左右
- 边界关系用轨道预报提前计算，不需实时重算

## 六、实验设计

### 6.1 因果链验证（第一步，两周内完成）

先用时序模型拟合掉周期项，看残差（异常项）和已知事件的对应关系：
- 数据：ITU/ESA公开流量统计 + 公开活动公告/气象数据
- 如果残差尖峰能对上事件 → 同时证明语义信号存在、传统方法抓不住

### 6.2 Baseline设计

1. PSO（粒子群优化）：纯数值方法
2. DRL：现有ML方法代表
3. 单星time-split MILP：性能上界参照
4. LLM without RAG：消融，证明RAG的作用
5. LLM+RAG without缓存复用：消融，证明缓存的作用
6. LLM+RAG without不确定性追踪：消融，证明不确定性模块的作用

### 6.3 分场景评估

| 场景 | 对比方法 | 预期结果 |
|------|---------|---------|
| 有语义信号的突发需求 | DRL、传统优化 | 你的方法赢 |
| 纯随机流量波动 | 传统优化 | 传统优化赢，你退化为补充 |
| 混合场景 | DRL | 语义信号占比越高你越有优势 |

### 6.4 评估指标

- UC（主指标）：未服务容量，对标MILP论文
- EC：过度分配容量
- TTS：服务等待时间
- 端到端决策延迟（拆分：LLM推理/工具调用/执行）
- 人工介入率（目标<5%）
- 快速路径命中率随时间增长曲线
- 不确定性估计准确率（AUROC）
- 组间协商最优性损失（对比单星MILP上界）

1. 第一个在LEO星座级beam-hopping上给出近精确的性能基准，有可量化的optimality gap
