# 一、研究背景（前人做到哪一步）

## 1.1 使用大语言模型评估忠实性

大语言模型生成回答中的幻觉问题，已经得到了广泛研究。

1. 一些研究提出，可以通过**少样本提示**的方式预测生成内容的事实正确性。然而，近期分析表明，在使用常规提示策略时，现有模型仍然**难以可靠地识别幻觉内容**。

2. 一些方法尝试将**模型生成的回答**，与**外部知识库**中的事实进行关联和核对。但是，在许多实际场景中，并**不一定存在可供使用的外部知识库**，因此这种方法并非总是可行。

3. 一种策略是**检查模型为各个词元分配的概率**。其基本假设是：与事实性回答相比，模型对幻觉回答的置信度通常应该更低。
- BARTScore 通过考察在**给定输入的情况下生成目标文本的条件概率**，来估计生成文本的事实性。
- Kadavath 等人采用了这一思路的一种变体，将**验证模型生成的回答是否正**确转换成一道**多项选择题**，让模型判断给定回答究竟是：他们观察到，大语言模型在回答多项选择题时，其输出概率通常具有较好的校准性。
- Azaria 和 Mitchell 在大语言模型某个隐藏层的表示上训练一个**监督分类器**，用来判断给定陈述是否为真。这种方法表现良好，但它要求研究者**能够访问模型内部的隐藏状态**。因此，对于只能通过 API 使用的大语言模型，这种方法并不适用。
- SelfCheckGPT 通过对同一个问题多次采样回答来解决 ChatGPT 和 GPT-4 这类无法访问词元概率的模型。它背后的核心思想是：**事实性回答通常更加稳定**。当一个回答符合事实时，对同一个问题进行多次采样所得到的回答，在语义上往往比较相似；而当回答包含幻觉时，不同采样结果之间通常更容易出现矛盾或差异。
## 1.2 文本生成系统的自动化评估

1. 大语言模型被用于自动评估**生成文本的其他质量维度**。

- GPTScore 使用提示词指定需要评估的方面，例如流畅性，然后根据某个自回归语言模型**为生成词元赋予的平均概率**，对文本片段进行评分。
- Yuan 等人此前也研究过**利用提示词指定评价维度**的思路。不过，他们使用的是一个规模较小、经过微调的语言模型，即 BART，并且没有观察到使用提示词所带来的明显优势。
- 一种方法是直接要求 ChatGPT 对给定回答的某个方面进行评价，例如：给出一个 0 到 100 之间的分数；或者按照五星制进行评分。令人注意的是，这种简单的方法也能够取得较好的结果。

局限：评价结果会受到提示词设计的影响。

2. 一些研究让大语言模型**从多个候选回答中选出最佳回答**。这种方法通常被用于比较不同大语言模型的性能。不过候选答案的**呈现顺序**可能会影响大语言模型的选择结果。

现有文本生成评估方法大多依赖一个或多个**参考答案**。BERTScore 和 MoverScore 使用预训练 BERT 模型生成的上下文表示，比较**模型生成回答与参考答案之间的相似度**。BARTScore 同样利用参考答案来计算不同评价维度，例如：
- **精确率**：通过“给定参考答案时，生成模型回答的概率”进行估计；
- **召回率**：通过“给定模型回答时，生成参考答案的概率”进行估计。

# 二、创新点与贡献

把**答案是否受到外部上下文支持**转化成一套可自动执行的原子陈述分解与验证流程，并将其做成可用的 RAG 评估工具。
## 2.1 提出 RAGAS

RAGAS 面向没有人工标准答案的场景，对 RAG 系统进行自动评估，并把评估拆成三个维度：
- 忠实性
评估对象：答案与检索上下文
核心问题：答案中的陈述是否受到上下文支持
- 答案相关性
评估对象：答案与问题
核心问题：答案是否真正回答了问题
- 上下文相关性
评估对象：检索上下文与问题
核心问题：检索内容是否集中、是否包含冗余信息
## 2.2 为三个维度设计了可自动计算的具体指标

- 忠实性：先把答案拆成若干独立陈述，再让 LLM 逐条判断：该陈述能否从给定上下文中推出？最后计算：被上下文支持的陈述数 ÷ 总陈述数。
- 答案相关性：让 LLM 根据答案反向生成若干可能的问题，再比较这些问题与原始问题的向量相似度。逻辑：如果这个答案确实回答了原问题，那么根据答案反推出的问题，应该
- 上下文相关性：让 LLM 从检索上下文中抽取回答问题真正需要的句子，然后计算：相关句子数 ÷ 上下文总句子数。
## 2.3 构建 WikiEval 人工评估数据集

构建了新的 WikiEval 数据集。基于 50 个维基百科页面构造问题、答案和上下文，并由两名人工标注者对三个维度进行成对比较。

# 三、实验与结论（数据说明了什么、有什么局限性）

## 3.1 RAGAS 比直接让 GPT 打分或排序更接近人工判断

作者将 RAGAS 与两个简单基线比较：
- GPT Score：直接让 ChatGPT 打 0～10 分；
- GPT Ranking：直接让 ChatGPT 在两个候选中选择更好的。

实验结果如下：

| 方法          |  忠实性 | 答案相关性 | 上下文相关性 |
| ----------- | ---: | ----: | -----: |
| RAGAS       | 0.95 |  0.78 |   0.70 |
| GPT Score   | 0.72 |  0.52 |   0.63 |
| GPT Ranking | 0.54 |  0.40 |   0.52 |
**将复杂评估任务分解**为陈述抽取、逐条验证、逆向问题生成等步骤，比直接要求 LLM 对完整答案打分或排序，更符合人工判断。

- 忠实性指标效果最好：先把答案拆成若干陈述，再逐条判断这些陈述能否由上下文支持，是一种比较可靠的忠实性评估方式。
- 答案相关性和上下文相关性更难评
## 3.2 JSON 输出能提高重复运行的一致性

使用 JSON 格式时，两次运行得到的 RAGAS 分数相关性更高、结果更稳定。因此作者认为，结构化输出能够：降低解析错误、提高可复现性、改善不同运行之间的一致性。
