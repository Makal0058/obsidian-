# 一、研究背景
## 1.1 前人做到哪一步

纳卫星（Nanosatellite）由于体积小、能源储备有限，需要在有限的计算能力和电池容量下执行遥感观测、通信及科学实验等任务。因此，研究人员提出了**离线纳卫星任务调度（Offline Nanosatellite Task Scheduling，ONTS）**问题，在卫星发射前根据轨道环境、任务需求和能源约束制定调度方案，以最大化任务服务质量（Quality of Service，QoS）。

早期研究已经建立了较为完整的数学优化模型，能够考虑**任务执行时间窗口、周期性、最小与最大执行时长、任务启动次数以及电池荷电状态**等约束。在求解方法上，研究人员先后采用混合整数线性规划（MILP）、列生成（Column Generation）、分支定价（Branch-and-Price）以及 Benders 分解等方法，提高复杂卫星任务调度问题的求解效率。

此外，已有研究引入遗传算法、图神经网络（GNN）等方法，以减少大规模调度问题的计算开销。其中，基于图神经网络的方法已经能够预测任务调度的可行性及近似最优解。与此同时，在一般资源受限项目调度领域，**多模式资源受限项目调度问题（Multi-Mode Resource-Constrained Project Scheduling Problem，MRCPSP）**已经允许任务采用不同执行模式，为纳卫星任务调度提供了进一步扩展的基础。
## 1.2 现有方法的主要问题

**第一个问题是多数研究仍采用固定任务运行模式，未充分考虑同一任务在不同运行模式下的功耗和执行时间差异。** 实际上，卫星任务可以采用高功耗、高执行速度的模式，也可以采用低功耗、低执行速度的模式。当太阳能供应不足或电池电量有限时，固定运行模式可能无法充分利用任务执行时间与能源消耗之间的权衡关系。

**第二个问题是引入多模式后，任务调度的组合搜索空间进一步扩大。** 调度算法不仅需要决定哪些任务在什么时间执行，还需要决定每项任务采用哪一种运行模式。任务调度与模式选择相互影响，使优化问题更加复杂。传统混合整数规划方法在大规模问题中可能面临较高的计算成本，而遗传算法等启发式方法虽然能够较快获得可行解，却难以保证全局最优性。

**第三个问题是现有分支定价方法难以高效处理多模式任务调度。** 已有方法主要采用单层分解结构，需要在同一求解过程中处理任务分配与复杂资源约束。对于多模式任务调度，传统定价子问题会更加复杂，可能影响列生成效率。

因此，**如何在保持最优性保证的同时，降低多模式任务调度的计算复杂度，成为本文需要解决的关键问题。**
## 1.3 本文的研究切入点

针对上述问题，本文将**多模式运行机制引入 ONTS**，建立新的混合整数线性规划模型。该模型允许任务选择不同的运行模式，每种模式对应不同的执行时间与功率消耗，并同时考虑任务时间窗口、周期性、启动次数以及电池能源约束。作者还通过引入辅助变量、有效不等式（Valid Inequalities）和覆盖割平面（Cover Cuts），增强数学模型的求解效率。

在算法设计方面，本文提出**嵌套分支定价算法（Nested Branch-and-Price，NB&P）**，将复杂的多模式调度问题分解为两个相互关联的优化层次。外层负责卫星任务调度，内层负责具体任务的运行模式选择，通过分层列生成逐步构建和优化调度方案，从而降低直接求解大规模组合优化问题的难度。

为了进一步提高计算效率，作者引入**内点正则化（Interior-Point Regularization）和 GPU 加速动态规划**。前者通过改善优化过程中的数值稳定性提高求解效率，后者利用 CUDA 并行计算加速定价子问题的求解。

**本文的核心思路是：通过数学模型强化、嵌套分解以及 GPU 并行计算，在满足卫星能源与任务约束的前提下，高效获得具有最优性保证的多模式任务调度方案。**
# 二、创新点与贡献
## 2.1 建立支持多模式运行的纳卫星任务调度模型

本文首先扩展了传统离线纳卫星任务调度（ONTS）模型，**允许同一任务在不同运行模式下执行，并联合优化任务执行时间与运行模式选择**。不同模式具有不同的功率消耗和执行时长，使调度算法能够根据卫星的能源供应情况选择更加合适的运行方式。

作者采用**混合整数线性规划（Mixed-Integer Linear Programming，MILP）**描述这一问题，在原有任务时间窗口、周期性和电池容量约束的基础上，引入与运行模式相关的决策变量。同时，提出新的有效不等式（Valid Inequalities）、辅助变量以及经过提升（Lifting）的多模式覆盖割平面（Cover Cuts），**收紧线性规划松弛，提高数学模型的求解效率**。

这一改进使卫星不再局限于固定功率运行，而是能够在任务执行速度、能源消耗与服务质量之间进行更灵活的权衡。
## 2.2 提出嵌套分支定价算法

本文最主要的算法创新是**嵌套分支定价（Nested Branch-and-Price，NB&P）**，通过两层列生成结构，将复杂的多模式任务调度问题分解为任务调度与运行模式选择两个层次。

**外层受限主问题（Outer Restricted Master Problem，ORMP）**负责决定各任务采用哪一种完整的执行方案，并协调不同任务之间的能源资源分配。**内层受限主问题（Inner Restricted Master Problem，IRMP）**则针对每个任务生成满足时间和运行模式约束的执行方案，并通过更底层的定价子问题搜索可改进当前解的模式调度方案。

**该方法不需要预先枚举所有可能的任务调度方案，而是利用对偶价格（Dual Prices）指导列生成，逐步引入有价值的候选方案。** 外层将对偶信息传递给内层，内层再利用动态规划求解各运行模式对应的定价子问题，从而减少对庞大组合搜索空间的直接探索。

此外，作者将列生成与**分支定界（Branch-and-Bound）**结合，并采用改进的伪成本分支策略（Pseudocost Branching），处理线性规划松弛产生的分数解，使算法能够在完整求解条件下获得具有最优性保证的整数调度方案。
## 2.3 引入内点正则化提高列生成稳定性

传统列生成算法在迭代过程中可能出现对偶变量波动较大、生成列的改善幅度不稳定等问题，导致额外的定价计算。针对这一问题，本文将**内点法（Interior-Point Method）与稳定化技术结合**，改善受限主问题的求解过程。

具体而言，作者采用内点正则化（Interior-Point Regularization）和专门的线性系统求解方式，并比较了增广形式（Augmented Form）与标准形式的计算效率。通过改善求解过程中的数值稳定性，减少列生成过程中不必要的迭代和定价调用。

**这一部分的贡献不是提出全新的内点法，而是将已有数值优化技术针对嵌套分支定价结构进行适配和改进**，使其能够更加高效地求解大规模多模式卫星任务调度问题。
## 2.4 利用 GPU 并行加速动态规划定价子问题

在嵌套分支定价算法中，内层需要针对不同任务和运行模式反复求解定价子问题。如果全部采用传统 CPU 串行计算，随着任务数量和时间范围增加，计算成本会显著上升。

为解决这一问题，本文设计了基于**动态规划（Dynamic Programming，DP）**的定价求解过程，并利用 CUDA 在 GPU 上进行并行计算。**通过并行处理不同任务与运行模式对应的动态规划计算，降低嵌套列生成过程中反复求解定价子问题的时间开销。**

这一设计充分利用了不同定价子问题之间的并行性，将数学分解算法与硬件并行计算结合。相比单纯改进优化模型，GPU 加速进一步提高了算法处理大规模调度实例的能力。
## 2.5 主要贡献总结

本文的贡献可以归纳为三个方面。

首先，在问题建模层面，**将多模式运行机制引入纳卫星任务调度问题**，并通过有效不等式和覆盖割平面改进混合整数线性规划模型，使任务调度能够更加充分地考虑功率与执行时间之间的权衡。

其次，在优化算法层面，**提出以双层列生成为核心的嵌套分支定价框架**，将任务执行方案选择与运行模式优化分层处理，并结合改进的分支策略，在提高求解效率的同时保留精确优化方法的最优性保证。

最后，在计算实现层面，**结合内点正则化、动态规划和 GPU 并行计算**，进一步提升大规模问题的求解效率。实验表明，多模式运行能够提高任务服务质量，而完整的嵌套分支定价求解框架在部分测试实例中实现了**超过 600 倍的计算加速**。
# 三、实验与结论
## 3.1 实验数据与设置

本文采用**基于真实轨道与卫星能源参数生成的仿真实例**，评价多模式纳卫星任务调度模型及嵌套分支定价算法（NB&P）的求解性能。实验首先利用轨道力学与卫星姿态模型计算太阳能发电曲线，考虑卫星轨道参数、太阳能电池板效率、卫星姿态以及地球遮挡造成的日食周期等因素。随后生成任务优先级、功率需求、执行时间窗口、最小与最大运行时长、任务启动次数及周期性约束等参数，以构建不同复杂程度的调度问题。

实验主要采用 **57 组多模式任务调度实例**，每个任务设置 3 种运行模式，任务数量为 4～18 个，调度时间段数量为 46～80 个。作者使用 C++ 实现算法，在 Ubuntu 24.04.1、64 GB 内存和 AMD Ryzen 9 5950X 处理器的服务器上运行，并使用 Gurobi 11.0 作为优化求解器。

实验围绕四个方面展开：首先比较原始 MILP 模型与加入有效不等式后的模型；其次比较单模式与多模式调度的服务质量；然后比较改进 MILP 与 NB&P 的求解时间和最优性间隙；最后分别评估内点稳定化、增广线性系统、GPU 动态规划和伪成本分支策略的加速效果。

评价指标包括**目标函数值（QoS）、计算时间、最优性间隙（Optimality Gap）和加速比（Speedup）**。其中，最优性间隙用于衡量当前可行解与最优值界之间的差距，间隙为 0 表示最优性已经得到证明。部分 MILP 对比实验设置了 3600 秒的时间限制，而稳定化和 CPU/GPU 对比实验采用 60 秒的时间限制。
## 3.2 实验结果说明了什么

**第一，多模式运行能够提高卫星任务调度的服务质量。**

根据表 4，在相同任务规模下，允许任务选择不同运行模式能够获得更高的 QoS。例如，当时间段数量为 47、任务数量为 4 时，单模式调度的目标值为 142，多模式调度提高至 205，增幅达到 **44.37%**。对于任务数量为 12 的测试实例，多模式方案仍能够带来约 **8.41%～14.75%** 的收益提升。

**这说明允许任务在执行速度和功率消耗之间进行选择，可以更充分地利用卫星有限的能源资源。**

**第二，有效不等式能够显著提高 MILP 模型的求解效率。**

根据表 3，当时间段数量为 46、任务数量为 6 时，原始模型需要 **1720.52 秒**才能证明最优解，而加入有效不等式后仅需要 **21.09 秒**，加速约 **81.58 倍**。

在部分规模更大的实例中，原始模型在 3600 秒内仍然存在最优性间隙，而强化后的模型能够在时限内证明最优性。**这说明强化约束能够收紧线性规划松弛，减少分支定界过程中需要探索的搜索空间。**

**第三，嵌套分支定价算法 NB&P 显著提高了复杂调度问题的求解效率。**

根据表 5，当时间段数量为 46、任务数量为 10 时，加入有效不等式的 MILP 模型需要 **3332.13 秒**，而 NB&P 只需要 **18.11 秒**，加速约 **184 倍**，并获得相同的最优目标值。

在另一个包含 14 个任务的实例中，MILP 在 3600 秒内仍存在 **0.86%** 的最优性间隙，而 NB&P 用 **5.72 秒**获得相同的目标值。以 MILP 的 3600 秒时间限制计算，两者的时间比约为 **629.48 倍**。需要区分的是，由于 MILP 未能在规定时间内证明最优性，该比值不能直接理解为两种算法完成相同最优性证明所需时间的精确加速比。

部分实例报告的时间比甚至超过 3000 倍。**这些结果表明，分层列生成与动态规划相结合，能够在部分复杂实例中显著降低求解时间，同时保持较高的解质量。**

**第四，内点稳定化与改进的分支策略能够进一步减少求解开销。**

根据图 2 和图 3，**内点稳定化能够减少不必要的定价迭代，而增广形式可以进一步提高线性系统的求解效率**。当时间段数量超过 60 时，稳定化在实验中带来约 **15%～20%** 的相对时间改善。

伪成本分支策略也优于实验中使用的强分支策略，尤其是在调度时间段数量较多的情况下，能够降低分支搜索的计算开销。这说明除数学分解结构外，数值优化方法和分支策略同样会影响整体求解效率。

**第五，GPU 并行动态规划能够改善大规模定价子问题的求解能力。**

在每组实例限制 60 秒的情况下，**纯 CPU 版本仅完成 57 组实例中的 17 组，而 GPU 版本能够求解更多实例**。这主要是因为嵌套定价过程中需要维护大量动态规划状态表，GPU 能够通过并行计算提高状态处理效率。

不过，在 CPU 能够完成的部分实例中，GPU 并不一定更快，说明并行计算也存在额外的数据传输和调度开销。

总体而言，**实验说明本文的性能提升来自数学模型强化、嵌套分支定价、数值稳定化与 GPU 并行计算的共同作用，而不是某一项技术的单独改进。** 同时，多模式运行机制提高了任务调度的服务质量，使算法能够在不同功率和执行时间之间进行更加灵活的权衡。
## 3.3 本论文有什么局限性

**第一个局限性是本文主要面向卫星发射前的离线任务规划，尚未直接验证复杂在轨环境中的实时调度性能。** 实验实例虽然采用轨道参数、太阳能发电模型和具有现实依据的任务约束生成，但仍属于仿真优化问题。实际卫星运行中可能出现太阳能输入预测误差、设备功耗波动和任务执行环境变化，而本文未直接在优化模型中处理这些不确定性。因此，算法在真实动态环境中的适应性仍需要进一步研究。

**第二个局限性是卫星能源和任务执行过程采用了简化的数学模型。** 论文以线性近似描述电池充放电及荷电状态，没有完整考虑充电效率变化、温度影响、电池老化和内阻等非线性因素。同时，模型采用固定时间间隔离散化调度周期。当时间粒度进一步缩小时，需要处理的决策变量和动态规划状态会增多，从而增加计算成本。

**第三个局限性是嵌套分支定价算法对 GPU 等并行计算资源存在较强依赖。** 论文发现纯 CPU 版本需要同时维护大量动态规划状态表，在较大实例中会面临明显的内存压力，甚至出现求解失败。另一方面，在 CPU 能够完成的 17 组实例中，CPU 版本反而比 GPU 版本更快，说明 GPU 并行计算存在数据传输和调度开销。

因此，**当前实现更适合具备较强并行计算能力的地面服务器，尚不能直接推广到计算和存储资源有限的星载设备。**

**第四个局限性是当前动态规划对多模式联合决策和跨迭代计算复用的利用仍有进一步研究空间。** 当前动态规划主要按照任务和运行模式分别构造定价子问题，论文在结论中提出，未来可以研究直接考虑模式切换的动态规划算法，以改进多模式调度的求解效率。

此外，本文重点评估计算时间和最优性，没有专门测量不同列生成迭代、不同分支节点之间的重复状态计算比例。**因此，目前尚不能判断跨迭代或跨分支节点的计算复用是否存在足够大的优化空间，也无法确定其能够带来多大的额外加速收益。**

总体而言，**本文的主要贡献是通过多模式任务建模、嵌套分支定价和 GPU 并行计算，提高了复杂纳卫星离线任务调度的求解效率。** 实验已经证明该框架在所测试实例中的有效性，但对于真实动态环境下的在线调度、更复杂的能源模型以及跨迭代计算复用等问题，仍有进一步研究空间。
# 四、对我的启发（对我的研究有什么值得参考的）
