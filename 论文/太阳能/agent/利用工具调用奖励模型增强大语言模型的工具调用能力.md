# 一、研究背景
## 1.1 前人做到哪一步

近年来，大语言模型（LLM）逐渐从单纯依赖内部知识进行推理，发展为能够自主调用外部工具的智能体。例如，模型可以利用搜索引擎获取最新信息，或者通过 Python 代码执行复杂计算，从而弥补自身知识过时和计算不准确等问题。

在此基础上，研究者开始利用强化学习（Reinforcement Learning，RL）提升模型的工具调用能力。以 Search-R1、ReSearch 和 ToRL 等方法为代表，已有研究通过 PPO、GRPO 等强化学习算法，使模型能够根据任务需求自主决定何时调用工具、调用什么工具，以及如何利用工具返回的信息完成推理。**这些研究已经证明，强化学习能够有效提升大语言模型的工具使用能力，但训练过程主要依赖最终答案的正确性作为奖励信号。**

与此同时，过程奖励模型（Process Reward Model，PRM）已经在数学推理等任务中得到广泛研究。与只评价最终答案的结果奖励模型不同，PRM 可以对中间推理步骤进行评价，为模型提供更细粒度的学习信号。然而，**已有 PRM 研究主要集中于数学推理步骤的正确性，对于智能体中间工具调用的质量、必要性及其强化学习优化方式，仍然缺乏充分研究。**
## 1.2 现有方法的主要问题

**第一个问题是最终结果奖励无法准确评价中间工具调用的贡献，容易产生错误的信用分配。** 在传统智能体强化学习中，模型通常根据最终答案是否正确获得奖励，而中间工具调用也会受到这一结果的影响。如果模型执行了合理的搜索操作，却在后续推理中错误理解了搜索结果，整条轨迹仍然可能受到负向更新，导致原本正确的工具调用行为也受到惩罚。

这种粗粒度的信用分配可能造成梯度冲突（Gradient Conflict）：同一种合理的工具调用行为，在成功轨迹中受到鼓励，却可能因为另一条轨迹的最终答案错误而受到抑制。**模型难以区分工具调用本身的质量与最终推理结果的正确性，从而影响工具使用策略的学习效率和训练稳定性。**

**第二个问题是如何构建适用于工具调用的过程奖励模型。** 与数学推理步骤不同，工具调用不仅需要判断操作是否正确，还需要考虑这次调用是否有必要、是否真正推动了任务完成。因此，现有研究尚未充分回答应该采用什么评价标准、需要多少训练数据，以及多大规模的奖励模型才能可靠地评价工具调用。

**第三个问题是过程奖励模型不能简单地接入现有强化学习算法。** 作者发现，如果直接将工具调用奖励纳入传统 GRPO 的组级优势估计，模型可能学会减少工具调用次数以避免潜在惩罚，而不是真正提高工具使用质量。这种奖励投机（Reward Hacking）说明，即使获得了更细粒度的过程奖励，也需要重新设计奖励分配与优势估计方式，才能有效改善强化学习。
## 1.3 本文的研究切入点

针对上述问题，本文提出工具调用奖励模型（Tool-call Reward Model，TRM），其核心思想是：**将工具调用本身的质量与最终答案的正确性分开评价，通过专门的过程奖励模型为每次工具调用提供独立的监督信号，从而改善强化学习中的信用分配问题。**

首先，在奖励模型构建方面，作者利用强大语言模型生成多轮工具调用轨迹，并对每次工具调用进行评价。评价包含两个维度：一是**必要性（Necessity）**，判断该调用是否为任务完成带来实质性进展；二是**质量（Quality）**，判断工具是否被正确使用、调用参数是否合理。只有两个条件同时满足，该次工具调用才被标记为有效。随后，作者利用这些标注数据训练专门的 TRM，使其能够预测每次工具调用的效用。

其次，在强化学习优化方面，作者没有简单地将工具调用评分与最终奖励合并，而是分别针对 PPO 和 GRPO 设计了更细粒度的奖励分配机制。对于 PPO，方法将工具调用奖励分配到对应调用结束的位置；对于 GRPO，则进一步引入**回合级优势估计（Turn-level Advantage Estimation）**，对中间工具调用奖励与最终结果奖励分别进行归一化处理，再用于策略更新。

注：
- **PPO：近端策略优化**
**根据行动获得的奖励更新模型，同时避免一次更新过大，导致原本学会的策略被破坏**。
1. **PPO 如何学习**
假设我们训练一个模型回答数学问题。模型生成一个答案，最终获得奖励 $R=1$。但这里有个问题：奖励为 1，是否意味着这个答案值得大幅鼓励？不一定。

因此，PPO 通常使用一个额外的价值模型（Critic），预测当前状态下未来能够获得多少累计奖励。例如：
- 模型实际获得的回报：$R=1$
- 价值模型预测的回报：$V(s)=0.6$

那么，一个简化的优势计算为：$A=R-V(s)=1-0.6=0.4$。这里：

- $A$：优势（Advantage）
- $R$：实际获得的回报
- $V(s)$：价值模型预测的预期回报

**优势为正，说明实际表现比预期好，应该鼓励这个行动**。如果实际回报只有 0.2，那么：$A=0.2-0.6=-0.4$，**优势为负，说明实际表现比预期差，应该降低采取这个行动的概率**。

实际 PPO 往往还会使用广义优势估计（Generalized Advantage Estimation，GAE），结合多个时间步的奖励和价值预测，而不只是进行一次简单相减。

2. **为什么 PPO 要限制更新幅度**
假设模型原本生成某个行动的概率是：$\pi_{\mathrm{old}}(a|s)=0.2$，训练后，新模型想把概率提高到 0.8。
这相当于一次更新使概率变成原来的 4 倍，可能导致训练不稳定。

PPO 使用裁剪（Clipping）机制，通过**限制新旧策略概率比对优化目标的影响，抑制过大的更新**。例如，设置裁剪范围为：$[1-\epsilon,1+\epsilon]=[0.8,1.2]$，当概率比超过该范围时，裁剪后的目标不再鼓励继续沿该方向扩大更新。需要注意，**这不是保证概率每次只能变化 20%，而是通过裁剪目标函数抑制过大的策略变化。**

因此，PPO 的两个重要组成部分是：**价值模型负责估计行动的优势，裁剪机制负责提高策略更新的稳定性。**

- GRPO：组相对策略优化
**不再训练额外的价值模型，而是让模型对同一个问题生成多个答案，通过比较这些答案的奖励来计算优势**。
1. **GRPO 如何学习**

假设给模型一道数学题，让它独立生成四个答案：

| 回答 | 奖励 |
| --- | --- |
| A | 1 |
| B | 1 |
| C | 0 |
| D | 0 |

首先计算这一组的平均奖励：$\mu=\frac{1+1+0+0}{4}=0.5$；再计算组内奖励的标准差：$\sigma=0.5$。随后，GRPO 计算每个回答的相对优势：$\hat A_i=\frac{R_i-\mu}{\sigma}$。得到：

| 回答 | 奖励 | 优势 |
| --- | --- | --- |
| A | 1 | +1 |
| B | 1 | +1 |
| C | 0 | -1 |
| D | 0 | -1 |

于是：

- A、B 的优势为正，模型会提高生成它们的概率。
- C、D 的优势为负，模型会降低生成它们的概率。

**整个过程不需要额外的价值模型，因为组内其他答案已经提供了比较基准。**

2. **为什么要使用相对奖励**
假设模型针对一道很难的题目，生成四个答案，奖励分别为：$R=[0.2,0.3,0.4,0.5]$。虽然最高奖励只有 0.5，但最后一个答案仍然是这一组中表现最好的。**GRPO 通过组内比较，可以鼓励这个相对更好的答案**。

不过，这也带来一个限制：**如果四个答案全部得到相同奖励，例如都为 0，那么普通的组内标准化无法提供有效的相对优势信号。**

3. **GRPO 是否也限制更新幅度**

是的。GRPO 并没有舍弃 PPO 的裁剪思想。GRPO 通常仍然使用类似 PPO 的裁剪策略目标，并可加入 KL 散度正则项，避免模型过度偏离参考策略。因此，**GRPO 并不是完全不同于 PPO 的优化机制，它主要改变了优势的估计方式。**

- **PPO 与 GRPO 最重要的区别**

| 比较维度 | PPO | GRPO |
| --- | --- | --- |
| 中文名称 | 近端策略优化 | 组相对策略优化 |
| 优势估计 | 通常依赖价值模型 | 比较同一问题的多个回答 |
| 价值模型 | 通常需要 | 不需要 |
| 策略更新 | 裁剪机制 | 通常也采用裁剪机制 |
| 训练特点 | 适用于一般序列决策问题 | 特别适合可以对同一问题采样多个回答的大模型训练 |
可以把它们理解成：

**PPO**：我先预测你应该得到多少奖励，再根据实际表现判断你做得好不好。
**GRPO**：我让你针对同一个问题尝试几次，再比较这些尝试中哪几次做得更好。
# 二、创新点与贡献
## 2.1 提出专门评价工具调用质量的奖励模型

本文的第一个创新点是**提出工具调用奖励模型（Tool-call Reward Model，TRM），将中间工具调用的质量与最终答案的正确性分开评价，从而为强化学习提供更细粒度的过程奖励。**

传统强化学习通常**根据最终答案是否正确评价整条轨迹**，这可能导致合理的工具调用因为后续推理错误而受到惩罚。TRM 则直接评价每次工具调用是否有效，使模型不必完全依赖最终结果判断中间操作的价值。作者将工具调用的评价划分为两个维度：

1. **必要性（Necessity）**：这次工具调用是否为完成任务带来了实质性进展，是否有必要执行。
2. **质量（Quality）**：工具是否被正确调用，调用参数是否合理，执行方式是否正确。

两个维度均采用二元评分，即满足条件为 1，否则为 0。最终标签定义为：$s_i=s_i^{ne}\cdot s_i^q$。其中，$s_i^{ne}$ 表示必要性评分，$s_i^q$ 表示质量评分。**只有工具调用既有必要、又被正确执行时，最终标签才为 1。**

例如，模型为了回答一个问题，连续搜索了三次。第一次搜索获取了必要的信息，第二次重复搜索已有内容，第三次使用错误关键词。即使最终答案正确，TRM 也能够区别这三次工具调用，而不是因为整条轨迹成功就将它们全部视为有效操作。
## 2.2 利用强语言模型构建工具调用奖励模型

本文的第二个贡献是**建立了一套利用强语言模型自动生成过程监督数据，并训练专用工具调用奖励模型的方法**，减少对人工逐步标注的依赖。具体训练流程包含三个阶段：

1. **轨迹生成**：利用 DeepSeek-R1 在具有搜索工具的环境中执行任务，生成包含多次工具调用的完整交互轨迹。
2. **工具调用标注**：将完整轨迹重新提供给 DeepSeek-R1，让其根据必要性和质量两个标准，为每次工具调用生成监督标签。
3. **奖励模型训练**：使用标注数据训练 TRM，使模型能够根据工具调用及其返回的信息，预测该次调用是否有效。

在模型结构上，TRM 使用 Transformer 作为基础网络，将原本用于预测下一个 Token 的语言建模输出层替换为**二分类层**。模型根据工具返回结果最后一个 Token 对应的隐藏状态，输出一个介于 0 和 1 之间的效用预测值：$\tilde{s}_i\in[0,1]$。

其中，$\tilde{s}_i$ 表示 TRM 预测的第 $i$ 次工具调用的有效程度。模型通过二元交叉熵损失进行训练，使预测值逐渐接近监督标签。

作者进一步研究了奖励模型规模与训练数据量的关系。实验发现，**使用约 10,000 条标注轨迹训练的 3B 参数 TRM，就能够取得较好的评价效果**，说明工具调用过程监督不一定需要非常大的奖励模型。
## 2.3 提出回合级信用分配机制

本文的第三个创新点是**将工具调用过程奖励与最终答案奖励分别分配到对应的交互位置，改善传统强化学习中所有步骤共享最终结果反馈的问题**。对于一条包含多次工具调用的轨迹，作者将中间工具调用的奖励交给 TRM 计算，而最终回答仍然根据答案是否正确获得结果奖励。

具体定义为：$\tilde{r}_i=\begin{cases}\tilde{s}_i,&1\le i\le n_\tau\\\mathbb{I}(y=y^*),&i=n_\tau+1\end{cases}$，其中：

- $\tilde{r}_i$：第 $i$ 个交互回合的奖励。
- $\tilde{s}_i$：TRM 对第 $i$ 次工具调用的评分。
- $n_\tau$：轨迹中的工具调用次数。
- $\mathbb{I}(y=y^*)$：答案是否正确，正确为 1，错误为 0。

由于 PPO 和 GRPO 实际在 Token 级别进行策略优化，而 TRM 的奖励定义在工具调用回合级别，因此作者进一步设计了奖励映射机制：**将每次工具调用的奖励放在对应工具调用动作的最后一个 Token 位置，将最终结果奖励放在答案的最后一个 Token 位置**。

在 PPO 中，作者利用这些奖励计算后续回报和优势，并通过参数 $\alpha$ 控制过程奖励的影响程度。这样，正确的工具调用即使出现在最终失败的轨迹中，也仍然能够提供正向的过程奖励信号。

需要明确的是，这种方法并非完全取消最终奖励对早期步骤的影响，而是通过引入独立的工具调用奖励，使信用分配更加细致。
## 2.4 改进 GRPO 的回合级优势估计

本文的第四个创新点是**针对 GRPO 设计回合级优势估计（Turn-level Advantage Estimation），避免直接混合过程奖励与结果奖励时产生不合理的训练行为。**

作者发现，如果简单地采用组级优势估计处理工具调用奖励，模型可能倾向于减少工具调用次数，而不是提高调用质量。这是因为较长的工具调用序列通常包含更多难以执行正确的操作，后续调用可能获得较低评分，从而使模型受到不合理的负向训练信号。为了解决这一问题，作者将两类奖励分开处理：

1. **工具调用奖励**：收集同一组轨迹中的所有工具调用评分，使用这些评分的均值与标准差进行归一化。
2. **最终答案奖励**：单独收集各条轨迹的最终结果奖励，在结果奖励组内进行归一化。

两类奖励归一化之后，再映射到对应的 Token 位置，并通过折扣累加得到 Token 级优势，用于 GRPO 的策略更新。**这种设计使中间工具调用不必直接与最终答案的奖励进行比较，而是分别获得相对评价，再共同影响策略优化**。

论文的消融实验表明，在其搜索问答实验中，采用回合级优势估计的准确率为 42.47%，高于采用传统组级估计时的 41.18%。这说明合理处理过程奖励的归一化方式，能够改善工具调用强化学习的效果。
## 2.5 验证过程奖励对工具调用能力的提升

在算法设计基础上，本文进一步通过搜索问答和 Python 代码辅助数学推理实验，验证 TRM 与 PPO、GRPO 结合的有效性。

在 Qwen2.5-3B 的搜索问答实验中，Search-R1-GRPO 的平均准确率为 42.33%，加入 TRM 后提升至 43.49%。在 Qwen2.5-7B 上，平均准确率由 46.90% 提升至 48.62%。

在代码辅助数学推理任务中，加入 TRM 同样能够提高整体表现。作者还通过消融实验发现，**只评价工具调用的必要性或者只评价质量，都不如同时考虑两个维度有效**。此外，TRM 对未见过的工具使用场景也表现出一定的泛化能力。

**总体而言，本文真正的贡献不仅是让 LLM 评价中间步骤，而是围绕工具调用构建了一套完整的过程奖励学习方法，包括双维度评价标准、专用奖励模型训练、回合级信用分配，以及适配 PPO 和 GRPO 的优化机制。**

与 Tree-GRPO 通过共享前缀和最终奖励间接产生过程偏好不同，**本文明确引入一个学习得到的奖励模型，对每次工具调用进行单独评价，并将这些评价用于强化学习。**
# 三、实验与结论
## 3.1 实验数据与设置

本文主要围绕两个问题展开实验：**一是能否使用少量标注数据训练出可靠的工具调用奖励模型（TRM）；二是将 TRM 引入 PPO 和 GRPO 后，能否提升大语言模型的工具使用能力与最终任务表现。**

实验主要涵盖两类任务：

1. **搜索问答任务（Search-based QA）**：包括 NQ、TriviaQA、PopQA、HotpotQA、2WikiMultiHopQA、MuSiQue 和 Bamboogle，共 7 个数据集。模型需要通过搜索工具获取信息，并完成单跳或多跳问答。
2. **代码辅助数学推理（Code-based Math）**：包括 AIME24、AIME25、MATH500、Olympiad 和 AMC23，共 5 个数据集。模型可以调用 Python 工具执行计算，辅助解决数学问题。

在奖励模型训练方面，作者利用 DeepSeek-R1 生成工具调用轨迹，并根据必要性与质量两个标准自动标注。其中，搜索任务主要采用 Qwen2.5-3B-Instruct 作为 TRM 基础模型，使用 10,000 条标注轨迹训练；代码任务采用 Qwen2.5-Math-1.5B，使用 20,000 条训练样本。

在强化学习实验中，搜索任务使用 Qwen2.5-3B-Instruct 和 Qwen2.5-7B-Instruct，数学任务使用 Qwen2.5-Math-1.5B 和 Qwen2.5-Math-7B。作者以 Search-R1 和 ToRL 为基础，分别比较引入 TRM 前后的 PPO、GRPO 表现，并与直接推理、SFT、RAG 等方法进行对照。

此外，论文还通过不同奖励模型规模、训练数据量、优势估计方式、奖励权重和工具调用评价标准等消融实验，分析各个模块的实际作用。
## 3.2 实验数据说明了什么

**第一，工具调用过程奖励能够稳定改善模型的最终任务表现，但在已有较强强化学习基线上的提升幅度相对有限。**

在搜索问答任务中，Qwen2.5-3B 使用 Search-R1-PPO 时，7 个数据集的平均准确率为 32.75%，引入 TRM 后提升至 34.93%；使用 GRPO 时，则由 42.33% 提升至 43.49%。

在 Qwen2.5-7B 上，PPO 的平均准确率由 37.94% 提升至 39.95%，GRPO 则由 46.90% 提升至 48.62%。这些结果说明，TRM 不依赖某一种特定的强化学习算法，在不同规模模型和优化方法下均能改善工具使用效果。

在代码辅助数学推理任务中，TRM 同样取得提升。Qwen2.5-Math-1.5B 使用 GRPO 时，平均准确率由 43.18% 提升至 45.42%；Qwen2.5-Math-7B 则由 52.19% 提升至 53.70%。其中，1.5B 模型在 AIME25 上由 19.33% 提升至 27.00%，表明更细粒度的工具调用反馈对于复杂数学推理也具有实际价值。

**第二，工具调用的必要性与质量需要同时考虑，单独优化其中一个维度并不能取得最佳效果。**

消融实验发现，仅使用质量评分容易使模型调用过多工具，从而引入无关信息；仅使用必要性评分虽然能够减少调用次数，却可能降低具体调用的质量。将两种评价结合后，模型能够在保持相对合理调用次数的同时获得更好的任务表现。

这说明，**有效的工具使用策略不仅要判断工具是否被正确执行，还需要判断这次调用是否真正有必要。** 过程奖励的设计必须同时考虑工具调用的有效性与效率，而不能单纯鼓励增加或减少工具调用。

**第三，回合级优势估计比直接使用组级优势估计更加有效，能够缓解模型主动减少工具调用的奖励投机问题。**

在 GRPO 的对照实验中，采用传统组级优势估计的准确率为 41.18%，而采用回合级优势估计后达到 42.47%。附录实验还发现，两种方法的平均工具调用次数分别为 2.36 次和 2.72 次。

这说明，将工具调用过程奖励与最终结果奖励分开归一化，可以减少模型因为后续工具调用评分较低而倾向于过早停止搜索的问题。**过程奖励是否有效，不仅取决于评分本身，还取决于奖励如何转换为策略优化所使用的优势信号。**

**第四，专门训练的中等规模奖励模型已经能够提供有效的过程监督，而且额外训练成本相对可控。**

作者比较了不同 TRM 模型规模和训练数据量，发现使用约 10,000 条标注轨迹训练的 1.5B、3B 模型表现较好，而更大的 7B 模型在相同数据规模下可能出现过拟合。这说明过程奖励模型不一定需要很大的参数规模，关键在于训练数据的质量及其与评价任务的匹配程度。

此外，在论文报告的计算环境中，加入 TRM 后，每个训练步骤的平均耗时由 56.9 秒增加至 61.9 秒，额外开销约为 8.8%。在更广泛的多工具任务 ReCall 上，模型的 F1 分数也由 39.71 提升至 43.28，初步表明 TRM 的作用并不局限于单一工具场景。

总体而言，**实验支持本文的核心结论：相比只依赖最终答案奖励，单独评价中间工具调用并合理分配奖励，能够改善工具使用策略和最终任务表现。**
## 3.3 本论文的局限性

**第一个局限是工具调用评分仍然依赖强语言模型生成的监督标签，其可靠性受到评分模型自身能力的限制。**

本文主要利用 DeepSeek-R1 判断工具调用的必要性和质量，再将这些标注用于训练 TRM。虽然作者进行了数据质量验证，但在抽样的 100 条轨迹中，人工核验得到的必要性和质量标签准确率均为 89%，多模型核验结果分别为 86% 和 75%。这说明自动生成的过程监督仍然存在一定误差。

对于复杂的多轮推理任务，某次工具调用看起来合理，并不意味着它确实提高了最终成功概率。因此，**TRM 学习到的主要是工具调用的必要性与执行质量，而不是每次工具调用对最终结果的精确因果贡献。**

**第二个局限是过程奖励主要针对工具调用，尚未充分解决完整推理过程中的信用分配问题。**

本文将一次工具调用作为主要评价单位，但智能体完成任务还涉及内部推理、信息整合、策略选择和最终答案生成等环节。例如，模型可能正确调用搜索工具，却在后续推理中错误理解信息；TRM 能够评价工具调用本身，却不能直接判断其他推理步骤分别造成了多少影响。

因此，本文改善的是工具调用层面的信用分配，而不是完整解决所有中间推理步骤的贡献识别问题。对于不依赖外部工具的纯语言推理任务，这种奖励机制也无法直接提供同样粒度的监督信号。

**第三个局限是方法仍然需要额外训练奖励模型，并对过程奖励权重进行调节。**

TRM 虽然不必在每次强化学习更新时调用 DeepSeek-R1 评分，但仍然需要事先生成标注数据、训练奖励模型，并在后续强化学习中执行额外的评分计算。论文报告的训练开销增加约 8.8%，而在 Best-of-N 推理评价中，每个样本的耗时由 0.14 秒增加至 0.21 秒，增加约 50%。

此外，奖励权重 $\alpha$ 也会影响最终表现。权重过小，过程奖励难以发挥作用；权重过大，则可能使模型过度关注工具调用，而忽略最终任务目标。因此，如何减少奖励模型开销，并使过程监督与最终结果奖励自适应地协调，仍然值得进一步研究。

**总体而言，本文验证了显式工具调用过程奖励对强化学习的有效性，但其核心限制仍然在于：过程评分不等于真实因果贡献，工具调用级监督也不能完全代替对整个推理过程的信用分配。**
