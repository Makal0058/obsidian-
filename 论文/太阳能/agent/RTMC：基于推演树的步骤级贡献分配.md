# 一、研究背景
## 1.1 前人做到哪一步

随着大语言模型能力的提升，强化学习逐渐从单轮问答任务扩展到需要多步骤决策的智能体任务。在这类任务中，模型不仅需要生成答案，还需要通过搜索、代码编辑、工具调用等操作与环境交互。每一步操作都可能影响后续决策，但任务是否成功往往要到整条执行轨迹结束后才能确定。

在强化学习训练方面，GRPO（组相对策略优化）通过对同一问题采样多条轨迹，并根据最终奖励计算组内相对优势，避免了额外训练价值网络。然而，**GRPO 将同一个优势值分配给整条轨迹中的所有动作，无法区分不同步骤对最终结果的贡献。**

为解决这一问题，已有研究开始探索更细粒度的贡献分配方法，主要包括以下几类：

1. **基于状态分组的方法**：GiGPO 将不同轨迹中具有相同锚点状态的动作分组比较，以估计步骤级优势，但依赖状态匹配。
2. **基于奖励模型的方法**：iStar 通过隐式过程奖励模型估计各步骤的价值，CriticSearch 则利用回顾式评价网络提供更密集的反馈。
3. **基于树搜索的方法**：AT2PO 通过树结构传播终局奖励，VinePPO 从中间状态展开额外轨迹，利用蒙特卡洛采样估计动作价值。
4. **基于已有轨迹构建树的方法**：TEMPO 将同一问题生成的多条回答组织为前缀树，通过共享前缀分析不同分支的优势，不需要额外采样轨迹。

**这些研究表明，贡献分配正在从整条轨迹统一评价，逐渐转向对中间状态和具体动作的独立评价。** 其中，利用多条轨迹之间的共同状态进行比较，为无需额外价值网络的步骤级优势估计提供了新的思路。
## 1.2 现有方法的主要问题

**现有方法的核心问题在于，最终奖励无法准确反映每个中间步骤的实际贡献。** 一条成功轨迹可能包含低效甚至错误的操作，而一条失败轨迹也可能包含正确且有价值的中间步骤。如果将最终奖励直接分配给全部动作，就可能错误地强化不良操作，同时抑制有价值的操作。

虽然可以引入价值网络或过程奖励模型，分别估计不同状态与动作的价值，但这些方法需要额外的模型训练与维护。在智能体任务中，状态空间庞大、动作序列较长，并且奖励通常十分稀疏，使得价值估计更加困难。**如何在不依赖额外价值网络的情况下，实现有效的步骤级贡献分配，仍然是一个重要问题。**

另一方面，已有树结构方法也受到状态匹配机制的限制。不同轨迹即使完成了相同的任务进展，也可能因为工具调用方式、操作顺序或文本表达不同，而产生完全不同的历史记录。例如，使用文件编辑器查看代码与使用终端命令读取相同文件，虽然操作效果相似，但原始记录并不相同。

如果使用完整历史记录判断状态是否相同，能够匹配的轨迹就非常有限，难以形成有效的共享分支。如果采用过于粗糙的状态表示，又可能把实际进展不同的轨迹错误地合并。因此，**如何识别不同轨迹之间具有相同或相似任务进展的状态，是利用树结构进行步骤级贡献分配的关键难点。**
## 1.3 本文的研究切入点

针对上述问题，本文提出 RTMC（Rollout-Tree Monte Carlo，推演树蒙特卡洛方法），核心思想是：**不再仅根据整条轨迹的最终奖励评价动作，而是将同一问题的多条执行轨迹组织成共享树，在相同状态下比较不同动作所产生的后续收益。**

作者观察到，同一问题的多次采样虽然可能产生不同的执行路径，但往往会经过具有相似任务进展的中间状态。这意味着，已有轨迹本身就包含了可用于比较不同决策的分支信息，不一定需要额外开展树搜索或训练价值网络。

为实现这一思路，本文设计了**状态—动作签名机制**，将复杂的交互历史转换为紧凑且可比较的结构化表示。例如，通过操作类型分类、文件查看范围分桶和代码内容哈希等方式，识别不同轨迹中具有相同操作效果或任务进展的状态，从而构建共享的推演树。

在此基础上，作者利用蒙特卡洛方法统计同一状态下不同动作对应的后续回报，分别估计动作价值与状态价值，再计算两者的差值作为步骤级优势。**这样可以利用已有采样轨迹，在不训练额外价值网络、不增加额外轨迹采样的情况下，为不同动作分配不同的训练信号。**

此外，考虑到许多中间状态只有少量轨迹访问，直接估计的优势可能为零或缺乏有效区分能力，本文进一步引入**基于先验的价值平滑机制**，将局部状态估计与整个问题组的成功率结合，以改善稀疏访问状态的优势估计。同时，针对软件工程任务中测试验证操作容易受到折扣奖励惩罚的问题，作者加入了任务特定的奖励修正。

总体而言，**本文的研究切入点不是设计新的强化学习优化目标，而是改进现有强化学习框架中的优势估计方式：通过状态抽象与跨轨迹回报统计，将轨迹级贡献分配细化为步骤级贡献分配。**
# 二、创新点与贡献
## 2.1 基于推演树的步骤级优势估计

本文提出 RTMC（Rollout-Tree Monte Carlo）优势估计方法，核心创新是**将同一问题生成的多条执行轨迹组织成共享树，并利用不同轨迹之间的状态重合与后续回报，实现步骤级贡献分配，而不需要额外训练价值网络**。

与 GRPO 对整条轨迹分配统一优势不同，RTMC 将轨迹拆分为状态—动作序列。当多条轨迹经过相同状态时，分别统计它们在该状态下执行不同动作后的累计回报，再通过蒙特卡洛方法估计动作价值和状态价值：

$\hat Q(s,a)=\frac{1}{N(s,a)}\sum_{i:(s_t^{(i)},a_t^{(i)})=(s,a)}G_t^{(i)}$

$\hat V(s)=\frac{\sum_a N(s,a)\hat Q(s,a)}{\sum_a N(s,a)}$

$\hat A(s,a)=\hat Q(s,a)-\hat V(s)$

其中，$\hat Q(s,a)$ 表示在状态 $s$ 下执行动作 $a$ 的平均后续回报，$\hat V(s)$ 表示该状态下的平均回报，两者的差值用于衡量当前动作相对于该状态平均水平的贡献。

**这种方法能够区分同一轨迹中不同步骤的贡献，使成功轨迹中的低质量动作受到抑制，同时允许失败轨迹中的有价值动作获得正向训练信号。** 此外，RTMC 直接复用强化学习训练过程中已经采样的轨迹，不需要额外展开搜索分支，其统计构建和优势计算的复杂度为 $O(NL)$，其中 $N$ 为轨迹数量，$L$ 为平均轨迹长度。
## 2.2 状态—动作签名机制

为了让不同轨迹能够共享中间状态，本文提出 **State-Action Signature（状态—动作签名）机制**，将复杂的智能体交互历史压缩为可比较的结构化表示，从而解决不同轨迹之间难以直接进行状态匹配的问题。

在动作表示方面，作者不直接比较工具名称，而是根据操作效果将动作划分为文件查看、搜索、修改、创建、执行、测试等类别。例如，通过文件编辑器读取文件与通过终端 `cat` 命令读取相同文件，可以归为同一类操作。与此同时，签名还记录操作范围、目标文件以及必要的执行结果，以保留不同操作之间的关键差异。

在状态表示方面，作者将此前执行的操作按文件汇总，并采用以下方式进行抽象：

1. **操作集合**：按文件记录已经执行的操作，弱化操作顺序对状态匹配的影响。
2. **范围分桶**：将文件内容按每 100 行划分为一个区间，减少不同查看范围造成的状态差异。
3. **内容哈希**：使用 4 位十六进制哈希表示代码修改内容，以区分针对同一文件的不同修改。
4. **全局标记**：记录思考次数、测试成功或失败次数等非文件操作信息。

**该机制的主要贡献是将状态匹配从原始文本历史的精确比较，转化为基于任务进展的结构化比较，使不同执行轨迹能够形成更多共享状态。** 不过，这种等价关系由人工设计的签名规则决定，并不保证匹配状态在实际环境中完全等价。

## 2.3 基于先验的价值平滑机制

由于不同轨迹会不断分叉，推演树中的许多状态只有一条轨迹访问。如果某个状态仅存在一个被采样的动作，那么其动作价值与状态价值相同，导致优势估计为零，无法提供有效的训练信号。

为此，本文提出 **Prior-Based Value Smoothing（基于先验的价值平滑）**，将局部状态价值与同一问题组的整体成功率相结合：

$\hat V'(s)=\frac{n(s)\hat V(s)+n_{\mathrm{prior}}V_{\mathrm{prior}}}{n(s)+n_{\mathrm{prior}}}$

其中，$n(s)$ 表示状态访问次数，$V_{\mathrm{prior}}$ 表示同一问题组的成功率，$n_{\mathrm{prior}}$ 为先验权重，实验中设置为 2。

当某个状态的访问次数较少时，估计结果更多地受到全局先验影响；随着访问次数增加，局部统计结果逐渐占据主导地位。**该机制缓解了稀疏访问状态无法产生有效优势信号的问题，使步骤级贡献分配能够覆盖更多中间状态。**

此外，针对软件工程任务中执行测试、验证代码修改等操作容易受到折扣回报惩罚的问题，作者增加了任务特定的奖励修正，对满足条件的验证操作给予额外奖励，以鼓励模型进行必要的代码检查。

## 2.4 实验验证与主要贡献

本文使用 Qwen3-Coder-30B-A3B-Instruct 作为基础模型，在 R2E-Gym 数据集上进行强化学习训练，并使用包含 500 个真实软件工程问题的 SWE-bench Verified 进行评估。作者通过逐步引入强化学习、步骤级奖励以及推演树优势估计，验证各模块对任务成功率的影响。

| 方法 | Pass@1 |
| --- | --- |
| Baseline（未进行强化学习） | 46.8% |
| GRPO | 49.0% |
| GRPO + Step Reward | 50.4% |
| RTMC（本文） | **52.2%** |

实验表明，**RTMC 相比 GRPO 提升 3.2 个百分点，相比加入步骤奖励的 GRPO 进一步提升 1.8 个百分点。** 此外，移除先验平滑后，RTMC 的 Pass@1 从 52.2% 降至 49.7%，说明先验平滑在缓解稀疏状态问题方面具有重要作用。

总体而言，**本文的主要贡献在于提出一种无需额外价值网络的步骤级优势估计框架，并通过状态—动作签名实现跨轨迹状态匹配，再利用先验价值平滑缓解稀疏采样问题。** 其创新重点不是设计新的推理搜索算法，而是充分利用已有执行轨迹中的共享状态和回报信息，使强化学习的贡献分配从整条轨迹细化到具体决策步骤。
# 三、实验与结论
## 3.1 实验数据与设置

本文使用 **Qwen3-Coder-30B-A3B-Instruct** 作为基础模型，采用 ROLL 框架进行强化学习训练，训练过程使用 32 张 GPU。训练数据来自 **R2E-Gym**，包含约 8,100 个软件工程任务实例，与测试集不存在任务重叠。模型通过 SWE-agent 架构与代码仓库交互，执行文件查看、搜索、修改、测试等操作，以完成真实的软件修复任务。

实验采用 **SWE-bench Verified** 作为测试基准，包含 500 个真实 GitHub 软件问题，使用 Pass@1 衡量任务解决能力，论文通过 3 次评估运行的多数投票确定结果。训练时，每轮采样 8 个问题，每个问题生成 8 条执行轨迹，共 64 条轨迹用于后续处理，并过滤结果完全一致的轨迹组。

为了验证各个改进模块的效果，作者设置了四组递进式对照实验：

1. **Baseline**：未经过强化学习训练的基础模型。
2. **GRPO**：根据最终奖励计算轨迹级优势。
3. **GRPO + Step Reward**：在 GRPO 基础上加入步骤级奖励，包括有效操作、无效操作和代码验证奖励。
4. **RTMC**：在相同步骤奖励基础上，利用推演树计算步骤级优势，并引入先验价值平滑机制。

此外，实验设置折扣因子为 0.99，先验权重为 2，验证操作奖励系数为 0.05，并通过消融实验检验先验价值平滑机制的实际作用。
## 3.2 实验结果说明了什么

在 SWE-bench Verified 上，四组方法的测试结果如下：

| 方法 | 成功解决数量 | Pass@1 |
| --- | --- | --- |
| Baseline | 234 / 500 | 46.8% |
| GRPO | 245 / 500 | 49.0% |
| GRPO + Step Reward | 252 / 500 | 50.4% |
| **RTMC** | **261 / 500** | **52.2%** |

首先，GRPO 相比基础模型提升了 2.2 个百分点，说明强化学习训练能够改善智能体的软件修复能力。在此基础上，引入步骤级奖励使 Pass@1 进一步提高到 50.4%，表明相比仅依赖最终结果，针对中间操作提供奖励有助于优化多步骤决策。

进一步采用 RTMC 后，**Pass@1 达到 52.2%，相比 GRPO 提升 3.2 个百分点，相比 GRPO + Step Reward 提升 1.8 个百分点。** 由于 RTMC 与 GRPO + Step Reward 使用相同的步骤奖励，二者之间的性能差异支持了作者的核心观点：**利用共享状态下不同动作的后续回报进行比较，可以提供比轨迹级优势更有效的训练信号。**

训练曲线也呈现出类似趋势。在 150 个优化步骤的训练过程中，RTMC 的任务解决率在后期整体高于传统 GRPO，并表现出较好的学习效果。这表明步骤级优势估计不仅改善了最终测试成绩，也有助于模型在训练过程中学习更有效的动作选择策略。

作者还通过消融实验检验先验价值平滑机制的作用：

| 实验配置 | Pass@1 |
| --- | --- |
| RTMC（不使用先验平滑） | 49.7% |
| RTMC（使用先验平滑） | **52.2%** |
| 性能差异 | **+2.5 个百分点** |

去除先验平滑后，Pass@1 从 52.2% 降至 49.7%，甚至低于 GRPO + Step Reward 的 50.4%。这说明在有限轨迹采样条件下，许多状态缺乏足够的访问次数，单纯依赖局部回报统计难以获得有效优势。**先验价值平滑是 RTMC 性能提升的重要组成部分，而不仅仅是一个辅助性的数值调整。**

总体来看，实验结果支持了本文的主要结论：**在不额外训练价值网络、不增加轨迹采样的条件下，通过跨轨迹状态匹配、蒙特卡洛回报统计和先验价值平滑，可以改善智能体强化学习中的步骤级贡献分配，并提高最终任务成功率。**
## 3.3 本论文的局限性

**第一，状态匹配依赖人工设计的签名规则，难以准确判断真实状态是否等价。** 本文通过操作分类、范围分桶、内容哈希等方式压缩交互历史，虽然增加了跨轨迹状态匹配的机会，但也可能忽略操作顺序、推理深度以及环境状态之间的重要差异。过于粗糙的签名可能错误合并不同状态，而过于精细的签名又会减少共享状态数量，影响后续统计。因此，RTMC 的优势估计效果仍然受到状态抽象质量的限制。

**第二，有限的轨迹采样导致大量状态缺乏有效的跨动作比较。** 实验中每个问题只生成 8 条轨迹，而智能体任务具有较大的状态空间，使得推演树中的多数状态仅被访问一次。虽然先验价值平滑能够缓解优势为零的问题，但其训练信号仍然依赖整个问题组的成功率，并不能代替真实的多动作回报比较。因此，在稀疏状态下，模型仍然难以准确判断某个动作对于最终结果的实际贡献。

**第三，方法的跨任务泛化能力尚未得到充分验证。** 本文仅使用一个基础模型，并主要在 SWE-bench Verified 上进行评估，其状态签名规则和代码验证奖励也针对软件工程任务设计。对于数学推理、信息检索以及其他智能体任务，可能需要重新设计状态表示和奖励修正方式，因此尚不能确定该方法能否直接推广到不同领域。

此外，作者观察到，强化学习训练虽然使模型能够解决部分原先无法解决的问题，但也会导致一些基础模型原本能够解决的任务出现退化。这说明更细粒度的优势估计能够改善整体性能，但**仍然无法保证所有任务上的推理能力都得到提升**。

总体而言，**RTMC 的主要局限不在于蒙特卡洛优势计算本身，而在于共享状态能否被准确识别，以及有限轨迹能否提供足够可靠的回报统计。** 未来可以考虑引入学习得到的状态表示、改进跨轨迹状态匹配方式，并在更多模型与任务环境中验证其有效性。
# 四、对我的启发（对我的研究有什么值得参考的）
