# 2. 任务感知的状态度量（解决「哪些状态值得放在一起」）

**任务感知的状态度量根据任务要求，学习一种能够衡量状态相似性的度量函数，再决定哪些分支可以共同计算**。接近**任务条件度量学习（Task-Conditioned Metric Learning）+ 动态共享计算**。
## 2.1 度量学习训练目标

希望得到有效共享计算的状态。训练时利用**历史任务**，**比较不同状态组合在共享计算与独立计算下的结果和成本**，让度量函数学会：

- $\text{共享收益高、结果误差小}\Rightarrow d(A,B)\text{ 小}$
- $\text{共享收益低或结果误差大}\Rightarrow d(A,B)\text{ 大}$

可以用成对监督或对比学习来实现。
## 1. 任务要求决定如何衡量状态

例如，同样是两颗卫星，电量分别为 33% 和 35%。

如果任务比较宽松，两者可能非常相似，因为这点电量差异几乎不影响后续任务。

但如果任务非常紧急，且能量资源接近任务所需水平，那么这 2% 的差异就可能变得重要。

因此，**相似性不仅由状态决定，也应该由任务要求决定**。

可以设计一个任务相关的距离函数：

$\boxed{d_\theta(s_A,s_B\mid t_A,t_B)}$

其中：

- $s_A,s_B$：两个分支的状态。
- $t_A,t_B$：各自的任务要求，例如紧急程度、时限、资源需求。
- $\theta$：需要学习的度量参数。
- $d_\theta$：两个状态在对应任务要求下的距离。

**距离越小，代表两个状态越适合共享计算。**
## 2. 方法

**构造任务相关的状态表示**：$z_i=\phi(s_i,t_i)$，然后使用加权距离：$\boxed{d(A,B)=\sqrt{\sum_{j=1}^{n}w_j(z_{Aj}-z_{Bj})^2}}$。这里的 $w_j$ 可以通过训练学习，并约束为非负值。

例如：

| 状态特征 | 宽松任务的权重 | 紧急任务的权重 |
|---|---|---|
| 当前电量 | 0.2 | 0.8 |
| 未来日照 | 0.4 | 0.9 |
| 数据缓存 | 0.3 | 0.4 |
| 任务剩余时间 | 0.2 | 1.0 |
进一步还可以让权重由任务决定，即 $w_j=w_j(t_A,t_B)$。这样，**不同任务要求下，同一对状态可以得到不同的相似度**。

**度量结果直接控制共同计算**：分支 A（状态 + 任务要求）与分支 B（状态 + 任务要求）共同输入任务条件度量学习模块，得到距离 $d$ 和共享权重 $g$。根据度量结果，执行不同的计算策略：

- **相近状态**：进入共享计算 C，尽可能合并相似计算。
- **不相近状态**：独立计算，保留原有计算路径。

距离可以通过 RBF 转换成连续共享门控：

$g(A,B)=\exp\left(-\frac{d(A,B)^2}{2\sigma^2}\right)$

- $g$ 接近 1：尽可能进入 C，共享计算。
- $g$ 处于中间：部分共享，剩余部分独立处理。
- $g$ 接近 0：主要执行独立计算。

对于多个分支，可以根据它们的度量结果形成多个共享计算簇。GMM 可以作为可选分组模块，而不是必须使用。

您的状态应该由**多个特征共同组成，而且这些特征之间可能存在相互补偿、相互依赖的关系**。

但这里还有一个更重要的问题：**多个特征最终应该产生一个总相似度，还是多个相似度？** 我觉得对于您的共享计算架构，后者可能更合适。

**多特征内积度量矩阵**：假设每个卫星状态有五个特征 $x_i=\begin{bmatrix}E_i\\\Delta E_i\\B_i\\T_i\\W_i\end{bmatrix}$，分别是当前电量、未来电量变化、缓存占用、任务剩余时间、地面站通信窗口。那么：$\boxed{d_\Omega(A,B)^2=(x_A-x_B)^T\Omega(x_A-x_B)}$，其中 $\Omega=\begin{bmatrix}\omega_{11}&\omega_{12}&\cdots&\omega_{15}\\\omega_{21}&\omega_{22}&\cdots&\omega_{25}\\\vdots&\vdots&\ddots&\vdots\\\omega_{51}&\omega_{52}&\cdots&\omega_{55}\end{bmatrix}$。

- **对角线元素**：衡量每个特征的重要程度。
- **非对角线元素**：描述不同特征在距离计算中的交互关系。
- **整个矩阵**：决定哪些状态组合在任务意义上比较接近。

要求 $\Omega$ 半正定，且实际使用前通常应对不同量纲的特征进行归一化。

**多个度量矩阵**：可以按具有计算联系的特征组划分，而不是每一个原始特征单独设一个矩阵。例如：

$\Omega_1:\text{能源相关特征}$
$\Omega_2:\text{缓存与通信相关特征}$
$\Omega_3:\text{任务时间与优先级相关特征}$

每组计算自己的距离：$d_k(A,B)^2=\Delta x_k^T\Omega_k(\tau)\Delta x_k$，其中 $\tau$ 表示任务要求，$\Delta x_k$ 是该组对应的状态特征差异。然后得到多个连续门控 $\boxed{g_k=\exp\left(-\frac{d_k(A,B)^2}{2\sigma_k^2}\right)}$。这样预处理头可以输出一个向量：$\mathbf{g}_{AB}=[g_1,g_2,g_3,\ldots,g_K]$。例如：**A、B 的多维共享门控（假设示例）**：

| 特征组 | 共享权重 |
|---|---|
| 能源状态 | 0.95 |
| 缓存通信 | 0.12 |
| 任务时间 | 0.87 |
能源和任务时间的共享权重较高，缓存通信的共享权重较低。实际能共享多少运算仍取决于 C 的实现。最终 **C 不必一次性合并 A、B 的全部状态，而是根据不同特征组的度量结果，有选择地共同计算**。当然，特征组如何划分、是否允许相互重叠，以及不同组是否真的对应可分离的计算，都需要后续实验验证。

我现在觉得您有两个可比较的架构：

- **单矩阵 $\Omega$**：得到一个整体相似度，决定 A、B 整体是否共享。
- **多矩阵 $\Omega_1,\ldots,\Omega_K$**：得到多个相似度，决定不同状态特征组各自的共享程度。

考虑到您最初希望只合并相近的计算，不相近的部分仍然独立计算，**我更推荐第二种**。

但这又引出一个很有价值的问题：**这些特征组需要人为划分，还是让度量学习自动发现特征之间的对应关系？** 我认为后者更贴近您最初的想法。
