# 一、研究背景（前人做到哪一步）
## 1.1 前人的研究大致经历了三步

1. **传统优化方法做计算卸载**  

已有工作尝试用 ADMM、博弈论等方法解决卫星边缘计算中的任务卸载问题，目标主要是降低计算复杂度、任务时延和能耗。但这类方法本身计算开销较大，在资源受限、拓扑快速变化的 LEO 卫星网络中，难以满足实时决策需求。

注：ADMM（交替方向乘子法）是一种经典的优化算法。把一个很难、很大的优化问题，拆成几个比较容易的小问题，然后轮流求解，反复迭代，直到大家的解逐渐协调一致。

2. **引入深度强化学习进行实时卸载**  

后续研究开始使用 DRL，根据当前网络状态实时决定任务如何卸载，例如利用深度 Q 学习进行任务卸载和资源分配。相比传统优化算法，DRL 更适合在线快速决策。

注：**Q-learning：用表格记 $Q(s,a)$；DQN：用神经网络预测** $Q(s,a)$

3. **从集中式 DRL 发展到多智能体 DRL**  

早期 DRL 方法通常由一个中心节点收集全局网络状态并统一做决策，但大规模 LEO 星座中，实时获取全局状态并不现实。因此研究开始转向多智能体框架，让每颗卫星依据自己的局部观测独立做卸载决策；已有工作也已经研究了 MADRL、POMDP 和 Actor-Critic 等方法。

注：MADRL（多智能体深度强化学习）：很多智能体一起学，并且需要考虑彼此之间的影响；POMDP（部分可观测马尔可夫决策过程）：卫星是在“信息不完整”的情况下做决策；Actor-Critic：一种强化学习结构，Actor 负责选动作，Critic 负责评价 Actor 选的动作好不好。
## 1.2 已有工作还存在两个主要不足

1. **没有充分考虑 LEO 卫星网络拓扑的高动态性**

2. **没有充分利用多级卸载的潜力**，即任务不仅能在接入卫星或地面云之间二选一，还可以先在多颗相邻卫星之间继续转发，寻找更合适的计算节点。

## 1.3 这篇论文要进一步解决的问题

**在动态 LEO 卫星网络中，让多颗卫星协同，通过多智能体强化学习实现“本地计算—邻星转发—地面云”之间的多级计算卸载。**

# 二、创新点与贡献

## 2.1 提出面向 LEO 卫星网络的多级计算卸载模型

注：LEO 卫星网络就是由很多颗**低轨道卫星**组成、彼此通信并为地面用户提供通信或计算服务的网络。

传统方法往往只考虑：接入卫星**本地计算**或直接卸载到**地面云**，本文进一步允许任务**接入卫星 → 邻星 → 邻星 → … → 最终计算节点**，即多个相邻 LEO 卫星可以协同处理计算任务，从而利用不同卫星之间不均衡的计算资源。

核心创新可以概括为**把邻星协同和多级转发引入卫星计算卸载。**
## 2.2 将计算卸载建模为 POMDP 多智能体决策问题

由于单颗卫星无法实时获取整个星座的全局状态，本文把每颗 LEO 卫星视为一个 Agent，并将卸载过程建模为 POMDP（部分可观测马尔可夫决策过程）

每颗卫星主要根据自身和邻居的局部观测来选择**本地执行**、**转发给四个邻星之一**、**卸载到地面云**。这使模型更符合动态、大规模 LEO 网络中“只能获得局部信息”的现实条件。
## 2.3 采用 MADRL + 集中训练、分布式执行

本文设计了多智能体深度强化学习方法，并采用集中训练、分布式执行（CTDE）。

训练阶段：Critic 利用全局状态帮助评价各个 Actor 的动作

执行阶段：每颗卫星只根据自己的局部观测，通过 Actor 独立做卸载决策

这样希望兼顾：全局协同能力 + 实际部署时的分布式实时决策。

另外，同一星座中的卫星高度同质，因此各 Actor 共享参数，也降低了模型训练和部署复杂度。
## 2.4 实验验证了多级 MADRL 卸载的效果

论文将所提方法与 OTC、OTAS、随机卸载、集中式 DQN、独立 DQN 等方法比较，主要考察：平均任务处理时延 ATPD、计算资源利用率 CRUR、卸载成本 COST、DRL 收敛速度。

注：
- **OTC（Offloading-to-Cloud）**：所有任务都直接卸载到最近的地面云，不在卫星上算
- **OTAS（Offloading-to-Access-Satellite）**：所有任务都强制在当前接入卫星上执行，不转给邻星，也不去云端
- **RO（Random Offloading，随机卸载）**：卫星随机决定自己算还是把任务转发出去，相当于一个“瞎选”的基线
- **CDRL（Centralized DRL / centralized-DQN）**：只有一个中央智能体，看整个网络的全局状态，统一决定所有任务怎么卸载
- **IDRL（Independent DRL / independent-DQN）**：每颗卫星自己维护一个 Q 网络，独立训练、独立决策，彼此之间不做联合学习。

实验表明，本文 MADRL 方法总体上优于多数基线，并且在三种 DRL 方法中表现出较好的收敛性能。

# 三、实验与结论（数据说明了什么、有什么局限性）
## 3.1 实验设置

作者使用 STK + Python 自行搭建了离散事件仿真平台，用来模拟地面用户分布、用户任务生成、任务传输与星上计算、卫星运动、LEO 网络拓扑动态变化

注：STK 是一个专门做**航天、卫星、轨道和通信链路仿真**的软件

仿真采用类似 Iridium 的 LEO 星座： 6 个轨道、每轨 11 颗卫星，共 66 颗、轨道高度 780 km、地面用户数量 15,000～27,000、每颗卫星总计算资源 6 GHz。

注：Iridium（铱星）是一个真实存在的商业卫星通信系统/星座名称。最初是美国推动建设的全球卫星通信系统，后来由 Iridium Communications 运营。
## 3.2 主要实验结果

 1. **MADRL 能显著降低任务处理时延**

随着用户数量增加，大部分传统方法的任务处理时延明显上升，而 MADRL 和集中式 CDRL 整体表现最好。

说明：让任务根据**实时负载**在**邻星之间**进行多级卸载，可以减少繁忙卫星上的排队，从而降低总体任务处理时延。

论文实验中，MADRL 与 CDRL 在 ATPD、CRUR 和 COST 三项指标上总体明显优于其他方法。

 2. **多级卸载能够提高整个星座的算力利用率**

由于地面用户分布不均，一些卫星负载很高，而另一些卫星大量空闲。MADRL 可以把任务繁忙卫星 → 空闲邻星，从而提高整个 LEO 星座的计算资源利用率。

说明论文提出的邻星协同机制，确实能够利用原本闲置的星上计算资源。

 3. **大多数任务其实不需要经过很多级转发**

这是论文一个挺有意思的实验结果：

- 约 59% 的任务直接在接入卫星完成
- 超过 80% 的任务在 4 级以内完成
- 需要 5 级及以上卸载的任务不到 3%

说明虽然论文允许任务不断在邻星之间转发，但**实际多数任务只需要很少几级**。因此后续可以限制最大卸载层数，减少状态空间和训练复杂度。

 4. **MADRL 的收敛性能较好**

作者比较了三种 DRL 方法的训练过程。MADRL 的 reward 较快稳定在约 -0.3，并且在三种 DRL 方法中表现出最好的收敛性能。

说明参数共享、集中训练以及多智能体协作有助于模型较稳定地学习卸载策略。

 5. **CDRL（集中式深度强化学习）有时效果更好，但实际部署困难**

一个很值得注意的结果是，用户规模较大时，CDRL 的性能有时略优于 MADRL。

作者的观点是，CDRL 能看到实时全局状态，因此理论上决策可能更优，但大规模动态卫星网络中很难实时收集整个星座的状态；而 MADRL 在运行时只需要局部观测，所以更具有实际部署可行性。

因此这里其实存在一个典型权衡：

- **CDRL：性能可能更好，但需要全局信息**
- **MADRL：牺牲少量性能，换取分布式可部署性**
## 3.3 论文最终结论

**在动态 LEO 卫星网络中，相比单纯“本地计算”或“直接上云”，利用邻星进行多级协同卸载，可以更充分利用整个星座的计算资源。**

再结合 MADRL + CTDE（集中式训练，分布式执行），训练时利用全局信息实现协同学习，执行时卫星依据局部观测分布式决策，能够在降低平均任务处理时延、提高计算资源利用率和降低卸载成本之间取得较好的综合效果。
## 3.4 局限性

1. **仍然主要是仿真实验**

论文的结果来自 STK + Python 仿真，而不是实际卫星系统部署。作者自己在结论中也明确表示，后续需要加入更真实的环境约束，以进一步提高模型可信度。

因此当前结果主要证明方法在所设定仿真模型下有效，还不能直接等同于真实星座中的实际性能。

2. **对地面云的假设较理想化**

论文假设 Cloud 拥有无限计算资源，因此任务在 Cloud 中不会排队。现实中的地面云当然也存在计算资源限制、排队、网络拥塞、网关容量限制。所以这一假设会简化 Cloud 端的计算模型。

3. **通信模型有所简化**

论文假设任务结果一般比原始任务小很多，因此结果返回过程中的传输时延可以近似忽略，只主要考虑传播时延；同时假定返回路径与上传路径相同。

真实卫星网络中的链路拥塞、动态路由、带宽竞争、链路中断可能会让情况更复杂。

4. **任务模型比较简单**

论文将每个任务建模为一个独立计算任务，主要包含任务大小、最大允许处理时延、用户、生成时间，且任务间相互独立。

它还没有考虑**一个任务由多个相互依赖的计算阶段组成**。

# 四、对我的启发

对卫星 MADRL 架构的一个新想法，让“全局协调层”和“本地自治层”在实际运行时同时存在。这对应一个“分层多智能体”（分层式卫星智能决策）的研究方向，分层多智能体强化学习。

例如可以设计**上层智能体决定跨区域任务迁移、整体负载均衡、资源统筹** $\to$ **下层智能体决定具体任务由哪颗邻星执行、怎么分配资源**
