1. **git status**
`git status` 作用是**查看当前 Git 仓库现在是什么状态**。
现在存在两个版本：
```text
Git 已经保存的版本：Git is a version control system.
        ↑
        │ 不一样了
        ↓
电脑里现在的文件：Git is a distributed version control system.
```
于是执行 `git status` 
```zsh
git status #查看当前 Git 仓库的状态。

>>> On branch master #当前位于 `master` 分支
>>> Changes not staged for commit: #有修改，但这些修改还没有加入暂存区
>>>   (use "git add <file>..." to update what will be committed) #使用 `git add <文件>`，把修改加入到即将提交的内容中
>>>   (use "git checkout -- <file>..." to discard changes in working directory) #使用 `git checkout -- <文件>`，丢弃工作区里对这个文件的修改

>>>     modified:   readme.txt #`readme.txt` 已经被修改

>>> no changes added to commit (use "git add" and/or "git commit -a") #目前没有任何修改被加入到待提交内容中
```
2. **git diff**
`git diff` 作用是**查看“你改了什么”**。
```zsh
git diff readme.txt #查看 `readme.txt` 文件具体发生了什么修改

>>> diff --git a/readme.txt b/readme.txt #正在比较修改前和修改后的 `readme.txt`：a/readme.txt → 修改前、b/readme.txt → 修改后
>>> index 46d49bf..9247db6 100644 #Git 内部记录的文件版本从 `46d49bf` 变成了 `9247db6`，文件权限模式是 `100644`
>>> --- a/readme.txt #下面的 `-` 内容代表修改前的文件。
>>> +++ b/readme.txt #下面的 `+` 内容代表修改后的文件。
>>> @@ -1,2 +1,2 @@ #这次比较的是文件从第 1 行开始的一段内容，修改前后都涉及 2 行。
>>> -Git is a version control system. #删除了这一行：Git 是一个版本控制系统。- 表示：旧内容被删除 / 被替换。
>>> +Git is a distributed version control system. #新增了这一行：Git 是一个分布式版本控制系统。+ 表示：新增内容
>>>  Git is free software. #Git 是自由软件。这一行前面既没有 -，也没有 +，说明这一行没有修改。
```
3. **git log**
`git log` 作用是查看先看以前存过哪些版本，顺序是 $\text{最新版本}\to\text{较旧版本}\to\text{最旧版本}$。
```zsh
git log

>>> commit 1094adb7... (HEAD -> master) #这是一次提交，它的 commit id（提交编号） 是 1094adb7...(现在正处于 master 分支的这个版本上)。版本3
>>> Author: Michael Liao <...> #作者：Michael Liao，以及他的 Git 邮箱。
>>> Date: ... #这次提交的日期和时间。
>>>
>>>     append GPL #提交说明（之前的 git commit -m "append GPL"）
>>>
>>> commit e475afc9... #版本2
>>> Author: Michael Liao <...>
>>> Date: ...
>>>
>>>     add distributed
>>>
>>> commit eaadf4e3... #版本1
>>> ...
>>>     wrote a readme file
```

注：
- `HEAD` = **我现在所在的版本**
- `master` = 当前这条分支的名字
- `HEAD^` = 上一个版本，也就是版本2。
- `HEAD^^` = 上上个版本，也就是版本1。
- `HEAD~100` = 往前 100 个版本。

如果觉得 `git log` 太长，可以输入：
```bash
git log --pretty=oneline
```
回复会简单很多：
```text
>>> 1094adb... (HEAD -> master) append GPL
>>> e475afc... add distributed
>>> eaadf4e... wrote a readme file
```
4. **git reset**
`git reset` 作用是**把 Git 当前的位置，重新指到某个版本或某个状态**。
```bash
git reset --hard HEAD^

>>> HEAD is now at e475afc add distributed #HEAD 现在已经移动到 e475afc，也就是 add distributed 这个版本。
```
于是：
```text
版本1 → 版本2 → 版本3
                  ↑
                 HEAD
```
变成：
```text
版本1 → 版本2 → 版本3
          ↑
         HEAD
```
同时，文件内容也会跟着恢复。

注：
- `--hard` 回退到上个版本的**已提交**状态，即不仅移动版本位置，还把暂存区和工作区一起恢复成那个版本的样子。
- `--soft` 回退到上个版本的**未提交**状态，即只移动 HEAD，修改仍然留在暂存区。
- `--mixed` 回退到上个版本**已添加但未提交**的状态，即 HEAD、暂存区、工作区一起恢复，未保存的修改可能被直接丢掉。
5. **git reflog**
`git reflog` 作用是**查看 HEAD 曾经移动过的记录，也就是近期干过哪些版本切换操作**。
```zsh
git reflog

>>> e475afc HEAD@{1}: reset: moving to HEAD^
>>> 1094adb HEAD@{2}: commit: append GPL
>>> e475afc HEAD@{3}: commit: add distributed
>>> eaadf4e HEAD@{4}: commit (initial): wrote a readme file
```
6. **暂存区**
Git 结构：$\text{工作区}\to\text{git add}\to\text{暂存区（Stage / Index）}\to\text{git commit}\to\text{版本库 / 当前分支}$

- **工作区（Working Directory）**：平时真正能看到、能编辑的项目文件夹。
- **暂存区（Stage / Index）**：准备下一次提交的修改先放这里。
- **版本库（Repository）**：`.git` 里面保存的提交历史、分支等信息。
比如：
```zsh
learngit/
├── readme.txt       ← 工作区
├── LICENSE          ← 工作区
└── .git/            ← Git 版本库
```
`.git` 里面又有暂存区、提交记录、分支等东西。

注：
- 为什么要有暂存区？
假设一次改了两个文件 `readme.txt`、`LICENSE`，但只想先提交 `readme.txt`，就可以 `git add readme.txt`。这时：
```zsh
readme.txt
→ 已经进入暂存区

LICENSE
→ 还留在工作区
```
- 两个不同状态：
1. **modified**`
```text
>>> modified: readme.txt
```
> 意思是 `readme.txt` 以前已经被 Git 管理过，现在又被修改了。但还没 `git add readme.txt`，所以它现在是**已修改，但未暂存**。
2. **Untracked files**
```text
>>> Untracked files:
>>> LICENSE
```
意思是 Git 发现这里多了一个 `LICENSE` 文件，但这个文件从来没被 `git add` 过，所以 Git 还没正式开始跟踪它。`Untracked` 就是**未跟踪**。
