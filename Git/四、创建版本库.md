1. **mkdir**
`mkdir` = **make directory**，创建文件夹。
```zsh
mkdir learngit
```
也就是新建一个叫 `learngit` 的目录。
2. **cd**
`cd` = **change directory**，进入这个文件夹。
```zsh
cd learngit
```
3. **pwd**
`pwd` = **print working directory**，显示“我现在在哪个目录”。
```zsh
pwd

>>>/Users/michael/learngit
```
4. **git init**
意思是**把当前这个普通文件夹初始化成 Git 仓库**。运行以后，Git 会在里面创建一个 `.git` 的隐藏文件夹。执行后，Git 会提示类似 `Initialized empty Git repository in /Users/michael/learngit/.git/`，翻译：已经在 `/Users/michael/learngit/` 中初始化了一个空 Git 仓库。
结构变成：
```zsh
learngit/
├── .git/
├── test.py
├── README.md
└── notes.txt
```

注：为什么平时看不到 `.git`？

因为 `.git` 前面有个 `.`在 macOS / Linux 里**以 `.` 开头的文件通常属于隐藏文件**。所以 Finder 默认不显示它。
```bash
git init
```
在终端输入 `ls` 只能看到普通文件；输入 `ls -a` 就能看到 `.`、`..`、`.git`。其中 `.` = 当前目录、`..` = 上一级目录、`.git` = Git 仓库数据。
`ls`：列出当前目录里的文件、`-a`：把隐藏文件也显示出来、`-h`：让文件大小更容易读，比如显示 `1K`、`2M`。
5. **git add**
它不是直接“生成一个版本”，而是**把 `readme.txt` 当前的修改放进暂存区，告诉 Git：这次提交我准备包含这个文件**。所以执行成功时通常什么都不显示，没有消息 = 通常就是成功
```zsh
git add readme.txt
```
也可以一次添加多个：
```bash
git add file1.txt
git add file2.txt file3.txt
```
也可以把当前目录下的修改一起加入暂存区
```bash
git add .
```
6. **git commit**
作用是**把暂存区里的内容正式保存成一个 Git 版本**。
```bash
git commit -m "wrote a readme file"
```
其中 `git commit → 提交版本`、`-m → 后面跟本次提交的说明`。这里 `"wrote a readme file"` 就是这次版本的说明。

注：
- 核心流程：
```text
工作区
  ↓ git add
暂存区
  ↓ git commit
本地仓库
```
- 为什么一定要分 `add` 和 `commit` 两步？

因为可能同时改了很多文件，但**不一定想全部放到同一次提交里**。例如：
```text
a.py     → 写了 Transformer
b.py     → 修了 bug
note.md  → 随手记了笔记
```
可能只想先提交：
```bash
git add a.py
git add b.py
```
然后：
```bash
git commit -m "implement transformer"
```
这样 `note.md` 就不会进入这次提交。
7. **`1 file changed, 2 insertions(+)` 是什么意思？**
提交成功后截图显示：
```text
1 file changed, 2 insertions(+)
```
表示：
```text
1 file changed → 这次提交涉及 1 个文件
2 insertions(+) → 新增了 2 行内容
```
8. **两个常见错误**
- 第一个：
```text
fatal: not a git repository
```
意思是**你现在所在的目录不是 Git 仓库**。
- 第二个：
```text
fatal: pathspec 'readme.txt' did not match any files
```
意思是Git 在当前目录里根本没找到 `readme.txt`。

常见原因是：
```text
文件名写错
文件不在当前目录
终端当前所在位置不对
```
