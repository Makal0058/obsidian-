## 一句话定位

第一篇系统综述"多个 LLM 在边缘网络协作"方向的论文，**无实验数据**，价值在于提供分类框架和开放问题列表，适合作为理论背书文献引用。

---

## 核心问题

单 LLM 三个根本缺陷：
1. **幻觉和偏见**：训练数据有限，单模型自信地给出错误答案
2. **跨域能力不足**：通信 LLM 遇到医疗查询就失效
3. **资源与能力矛盾**：足够强大的 LLM 跑不进边缘设备

> [!note] 幻觉的根本原因
> 模型学的是统计关联而非因果理解。o1/o3 的长链推理大幅缓解了推理类幻觉，但知识类幻觉（编造事实）和分布外幻觉仍然存在。真正的解法方向是**世界模型（World Model）**——让 AI 建立内部因果模型，能"做实验"而非靠统计猜测。在世界模型成熟之前，RAG 是最务实的工程补丁。

## 三种 Multi-LLM 协作模式

| 模式 | 机制 | 适合场景 | 卫星可行性 |
|------|------|---------|-----------|
| **协作型** | 分工合作，各处理擅长子任务 | 复杂多域任务 | ✅ 单向流水线，延迟可控 |
| **竞争型** | 互相辩论质疑，收敛到更可靠答案 | 减少幻觉 | ❌ 多轮交互，卫星飞走了 |
| **集成型** | 并行独立生成，投票/加权平均 | 提高可靠性 | ⚠️ 需等所有节点返回，延迟不可控 |

> [!warning] 卫星场景结论
> 只有协作型可行。竞争型和集成型的多轮交互在卫星覆盖窗口内无法完成。

## 关键使能技术（与我的研究相关）

### LLM Cascading（级联）
先用小模型，置信度不够再升级大模型。**现有工作用固定阈值**——这是我方向二的切入点：用 RL 让阈值动态学习。

### 记忆共享
多 Agent 共享记忆库，开放问题：
- 谁能访问谁的记忆？
- 如何防止错误记忆污染整个系统？
- 隐私如何保证？

→ 和我的分布式 RAG 知识库面临完全相同的挑战。

### 可信 Multi-LLM：加权拜占庭容错（Weighted BFT）

**类比信用评分**：

| 信用评分 | BFT 信任分 |
|---------|-----------|
| 历史还款记录好 → 信用分高 | 历史决策准确 → 信任分高 |
| 贷款额度大、利率低 | 投票权重大、影响力强 |
| 央行征信不可篡改 | 区块链记录不可篡改 |
| 新用户冷启动问题 | 新节点冷启动问题 |

机制：每个 LLM 节点有历史信任分，投票时按分数加权，"坏节点"总权重不超过阈值则整体决策不受影响。区块链记录所有投票历史防止篡改。

## 四个应用场景（速览）

- **老年护理**：医疗+家居+对话三个专职 LLM 协作，单 LLM 覆盖不了所有域
- **智能电网**：多 UAV 各自一个 LLM 分析图像，边缘汇总 LLM 综合结果
- **智能交通**：路口 LLM + 城市协调 LLM + 车辆 LLM 分层架构
- **低空经济（LAENets）**：路径规划+碰撞避免+任务调度三 LLM 分工

## 关键比喻：导师与研究生

> 导师（大 LLM）懂得多但精力有限；研究生（小模型）懂得少但精力充足。导师接活派具体任务，研究生独立干活，结果给导师过目修改，发稿。

| 比喻 | 系统角色 |
|------|---------|
| 导师接活派任务 | 大 LLM 任务编排/动态路由 |
| 研究生独立干活 | 小模型本地推理，无需频繁请示 |
| 不会的才去问导师 | 置信度低才触发大 LLM（RL触发机制） |
| 导师不可能24小时在线 | 卫星高延迟，大 LLM 不能实时调用 |
| 做多了积累经验，越来越少请示 | 记忆库积累后快速路径命中率提升 |
| 新研究生需要培训 | 新场景需要蒸馏/微调 |

> [!tip] 论文写作建议
> 这个比喻写进 Introduction 做 motivation，审稿人一下子就懂了。

## 对我两个研究方向的价值

**方向一（卫星故障预测）**：
- BFT 信任分机制 → 不同卫星组对同一故障给出不一致判断时，用加权投票提高可靠性
- 竞争型不可用 → 强化了"预测性+本地快速决策"的必要性

**方向二（动态推理+分布式RAG）**：
- LLM Cascading 的固定阈值缺陷 → 我的 RL 自适应阈值的直接 motivation
- 记忆共享开放问题列表 → 我需要解决的具体技术挑战已经被这篇论文定义好了
- 论文明确说 RAG+Multi-LLM 是开放方向 → 发表空间有保证
