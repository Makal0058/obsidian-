## 1. 它在解决什么问题

**现有方法的核心缺陷**：传统深度学习用于无线网络是个"黑箱"——

- 输入网络状态 → 输出决策，中间过程不透明，运维人员无法理解或信任
- 泛化能力弱：遇到训练数据里没出现过的场景（新型干扰、未知拓扑）就失效
- 多步骤决策无能：复杂任务需要拆解推理，纯端到端学习做不到
- 每个任务都需要单独训练一个专用模型，成本高

**现有综述的空白**：
- 讲"LLM 用于无线网络"的综述 → 不讲推理方法本身
- 讲"AI 推理技术"的综述 → 不结合无线网络各层的具体特性
- **本文填的空**：推理方法 × 网络协议栈五层，系统性对应

## 2. 核心方法（一句话）

> 将 LLM 的推理技术（CoT、RAG、ReAct、ToT 等）按**提示策略 / 架构创新 / 学习范式**三类分类，并逐层（物理层→链路层→网络层→传输层→应用层）分析每类方法如何解决该层的核心挑战。

### 推理方法三大类

| 类别   | 代表方法                                  | 核心思想              | 适用场景             |
| ---- | ------------------------------------- | ----------------- | ---------------- |
| 提示策略 | CoT、ToT、Self-Consistency              | 让 LLM 写出推理步骤，不改模型 | 需要可解释性、快速适配新任务   |
| 架构创新 | RAG、ReAct、PAL、GNN、Neuro-Symbolic      | 给 LLM 挂外部工具/知识库   | 需要实时知识、精确计算、工具调用 |
| 学习范式 | Self-Refinement、CoT Distillation、RLHF | 在训练/迭代阶段强化推理能力    | 频繁使用、边缘部署小模型     |

### RAG 的典型用法（本文）

- **信号识别**：把调制方式特征存入知识库，遇到未知信号动态检索比对，无需重新训练
- **故障诊断**：实时检索设备手册、历史故障日志，一步步推理得出带解释的诊断结论
- **数学建模辅助**：检索通信专家知识（干扰模型公式、约束条件），帮 LLM 把自然语言需求翻译成优化问题

### Agent 的典型用法（本文）

- **ReAct**：推理和行动交替执行，边想边查工具，故障排查全程可追溯
- **PAL**：LLM 写代码 + 解释器执行，解决 LLM 数值计算不准的问题
- **ToT**：多路径并行规划，比较优劣后剪枝，接近最优解且计算量远低于暴力搜索
- **多 Agent**：多个专职 Agent 分工协作（无线资源 / 核心网 / 安全），通过自然语言通信

## 3. 结论 / 效果

**总体结论**：推理型 AI 相比传统黑箱 AI 在以下维度有系统性优势——

- ✅ 决策过程透明，运维人员可验证
- ✅ 遇到未见场景仍能泛化（靠推理而非记忆）
- ✅ 可融合领域知识（手册、规范、历史经验）

**具体实验数据**：
- CoT + PAL 做波束成形功率分配 → 频谱效率提升 **50%**
- GNN 在 50 用户网络上训练 → 泛化到 1000 用户仍接近最优
- Neuro-Symbolic AI 做语义通信干扰抑制 → 语义表示压缩 **23%**，可靠性提升 **63%**

**四个未来研究方向**：
1. **Agentic AI**：多 Agent 自主网络管理，目标是"自驾网络"
2. **数据高效学习**：元学习、小样本迁移，解决无线场景标注数据稀缺
3. **边缘部署**：大模型量化/蒸馏/任务分层，跑在基站和终端上
4. **可靠性**：自验证循环、模拟器沙盒验证，防止幻觉决策导致网络中断

## 4. 我的改进 Idea

> [!tip] 核心思路：预测性闭环 Agent + 动态知识库 + 卫星场景

### 问题重定义

卫星硬件坏了无法修复，所以"修复"的重心应该转移：

- ❌ 硬件故障修复（不现实，无人上去换零件）
- ✅ 软件/配置层自动调整
- ✅ **故障前预测 + 自动任务迁移/降级**（graceful degradation）
- ✅ 历史经验自动积累回知识库

### 具体 Idea

**预测性自主故障管理 Agent for LEO 卫星网络**

```
监控异常征兆 → 推理预判故障 → 提前切走任务 → 重规划星座分工 → 经验写回知识库
```

**三个技术贡献点**：

1. **预测性而非响应性**：在故障真正发生前识别征兆（预测窗口哪怕几分钟也有价值）
2. **闭环执行**：Agent 不只诊断，还自动触发任务迁移和降级策略，并验证执行结果
3. **动态 RAG 知识库**：每次成功处理一个故障，将"问题-原因-解法"自动写回知识库，系统随时间越来越聪明

**卫星场景的特殊 Motivation**：
- 时延高（无法频繁人工干预）→ 自主 Agent 价值更大
- 拓扑动态变化（卫星持续移动）→ 实时推理优于静态规则
- 硬件无法修复 → 预测和降级比修复更重要

### 与现有论文的差异

| 对比维度 | 本文（综述） | SCNOC-Agentic | 我的 Idea |
