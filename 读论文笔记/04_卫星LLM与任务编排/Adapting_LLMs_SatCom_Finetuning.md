## 一句话定位

用 ESA 私有 PDF 语料对 Llama-3 和 Mistral 7B 做领域微调，结论是**微调 > RAG > 裸模型**。但对动态知识库场景（如故障预测）而言，RAG 的灵活性优势更大，微调每次更新知识都需要重新训练，不适合持续写入的场景。

---

## 核心结论（速览）

| 对比 | 结论 |
|------|------|
| 微调 vs 裸模型 | 提升 **6.6%** |
| 微调 vs RAG | 微调显著更好 |
| 第一轮微调（原始文本）vs 裸模型 | **反而更差** |
| 第二轮微调（Q&A格式）vs 裸模型 | 稳定提升 |
| 8-bit 量化 vs 全精度 | 性能损失极小，文件压缩到 7-8 GB |

> [!warning] 结论的适用边界
> 微调优于RAG的结论成立于**静态知识库**场景。动态场景（持续写入新经验）下RAG更合适——直接append，无需重新训练。

## 两个有价值的工程细节

### 1. PDF 提取流水线（踩坑经验）

处理含表格的技术文档：

```
主文本提取：Unstructured（保留位置元数据，支持多格式）
表格提取：Camelot（lattice模式，最准确）
两者结合：用Unstructured位置信息过滤Camelot的误识别
```

**为什么表格很重要**：卫星通信文档里大量关键参数（信噪比、功率预算、频段分配）都在表格里，跳过表格 = 丢掉核心专业知识。

### 2. Q&A 格式知识存储（核心洞察）

**第一轮微调失败的根本原因**：原始文本训练 → 模型学的是"文档补全"而非"问答"，训练目标和使用目标不对齐。

**解决方案**：用大模型把原始文档转成 Q&A 对再训练/存储。

**为什么 Q&A 格式更好**（类比考试）：
> 考试时大脑检索的是"这道题对应什么解法"，而不是"从课本里找答案"。Q&A 格式让检索时的查询（问题）和存储的知识（问题-答案对）在语义空间高度对齐，命中率大幅提升。

## 对我的研究方向的启示

> [!tip] 故障记忆库应该用 Q&A 格式存储

**不要存这种格式**：
```
"2024年3月，卫星X发生调制解调板故障，
表现为功率骤降+误码率上升，处理方式为..."
```

**应该存这种格式**：
```
Q: 当出现[功率骤降 + 误码率上升 + 温度正常]时，
   可能是什么故障？
A: 大概率是调制解调板异常，建议先检查...
```

**好处**：
- Agent 拿实时异常征兆检索，直接命中相似"症状描述"
- 格式紧凑，适合星间链路低带宽传输（类似通信去冗余）
- 格式统一，跨卫星组同步时无需协商格式，地面整合直接合并
- 自动质量过滤：Q&A 格式下 LLM 评估质量更容易自动化

**写回知识库的闭环**：
```
故障处理完成
    ↓
LLM 自动将处理过程转成 Q&A 对
    ↓
写入本地知识库
    ↓
定期同步至地面站
```

### 两级知识生产架构

本地（卫星）和地面分工：

| 层级 | 职责 | 原因 |
|------|------|------|
| 卫星本地 | 快速匹配已知故障模式 | 低延迟，实时响应 |
| 地面强算力 | 深度挖掘潜在Q&A | 跨卫星、跨时间关联分析 |

**地面独有的能力**：发现"征兆A + 征兆B 同时出现时，三天后大概率发生故障C"这类**跨事件隐性规律**，本地 LLM 没有足够上下文发现这类关联。

> **最佳实践**：卫星本地保留 Q&A 知识库用于快速检索，同时定期上传完整原始日志至地面站，地面站从日志中挖掘新 Q&A，下发给各组更新知识库。

## 可直接复用的工具链

```
PDF处理：Unstructured + Camelot
Q&A生成：Mistral Large（120B）或类似大模型
微调：LoRA + QLoRA（单卡48GB可跑7B模型，约8小时）
本地部署：LM Studio / Ollama / vLLM
向量库：FAISS / Qdrant
```
