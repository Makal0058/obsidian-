## 核心问题

SAGSIN 边缘网络的任务编排依赖**静态 DAG**——提前固定任务分解方案，网络状态一变就失效。需要从"静态规划"变成"动态自适应 AI 原生规划"。

---

## 核心方法：L-HTN 两层框架

**HTN**（层次任务网络）：把复杂任务递归拆成子任务，约束明确但规则死板。
**LLM**：灵活、知识广，但缺乏精确领域约束。
**L-HTN = 用 HTN 约束 LLM，用 LLM 填补 HTN 空白。**

```
高层规划（LLM + HTN）
  → 把抽象任务分解成 DAG 子任务
  → HTN 保证不违反领域约束
  → LLM 用 CoT/ToT 处理模糊情况
  → 预生成"场景数据库"（各种情况提前规划好）
        ↓
低层执行（多 Agent DRL）
  → 把高层 DAG 转化为每台设备的具体动作
  → 根据本地实时状态动态适应
```

**三条链**：任务链（做什么）→ 服务链（用什么模型做）→ 算力链（在哪里做）

**模型落地策略**：模型分割、知识蒸馏、量化压缩、联邦学习

# 研究方向二：面向低轨卫星星座的轻量化 LLM 动态推理框架

> [!info] 方向定位
> - **独立于**卫星故障预测方向（方向一）
> - **目标级别**：顶会 / 一区期刊
> - **核心问题**：边缘网络中 LLM 推理延迟 vs 决策质量的权衡

---

## 问题来源

现有动态任务编排方案（包括 L-HTN、SCNOC 等）的共同缺陷：

1. **每次任务都调用 LLM 决策** → 开销可能比静态配置还大
2. **RAG 检索本身有延迟** → 知识库越大越慢
3. **没有解决"什么时候值得深度推理"这个元问题**

---

## 核心架构

### 第一层：两级推理 + RL 触发机制

```
任务到来
   ↓
RAG 匹配本地记忆库
   ↓
[相似度高] ──→ 快速路径：直接复用历史决策（低延迟）
[相似度低 / 异常] ──→ 慢速路径：触发 LLM 深度推理
   ↓
执行结果 → RL 打分
   快速路径成功 → 正奖励（鼓励走缓存）
   快速路径失败 → 负奖励（提高触发阈值）
   慢速路径成功 → 正奖励 + 写回记忆库
   慢速路径失败 → 负奖励
   ↓
RL 持续优化"何时触发慢速路径"的决策边界
```

**关键创新**：RL 学的不是"怎么分配任务"，而是**"什么时候值得花代价深度推理"**——元决策问题，现有工作未专门研究。

**自我进化特性**：记忆库积累越多，快速路径命中率越高，系统越用越快。

### 第二层：分布式 RAG（星座分组架构）

对齐 Starlink 实际架构，卫星按轨道区域分组：

```
地面用户
   ↓ 访问最近卫星（毫秒级）
[小组 A]  3-6 颗卫星，共享本组记忆库副本
   ↓ 星间链路（秒级，有延迟但可接受）
[小组 B]  相邻小组，存储不同区域知识
   ↓ （尽量避免）
[地面服务器集群]  全局知识库，最后手段
```

**检索优先级**：本地命中 → 组内其他卫星 → 邻近小组 → 地面站

**为什么分组**：
- 单星存全量知识 → 硬件成本高、访问慢
- 纯分散无组织 → 跨星查询延迟不可控
- 分组 = 在硬件约束和延迟之间找平衡

### 第三层（留给未来工作）：知识分片优化

RL 动态优化"把哪类记忆存在哪组卫星"，最小化平均查询延迟。

---

## 知识同步机制（类 Git）

```
组内卫星
  → 实时读写本地记忆（快，无延迟）
  → 组内副本同步（星间链路，组内一致性）
        ↓ 定期
地面服务器集群
  → 整合多组上传的记忆
  → 去重、纠错、优化（清洗低质量经验）
  → 推送更新回各小组
        ↓
各小组拉取更新，替换本地旧版本
```

类比：**组内 = 工作区，定期同步 = git push/pull，地面站 = 远端仓库**

**地面站的额外职责**：
- 纠错：过滤因异常情况写入的错误经验
- 优化：合并相似决策，压缩记忆库大小
- 全局视角：跨小组的知识整合（某小组遇到的罕见故障，同步给所有组）

---

## 技术贡献点（投稿时可描述为）

> 提出面向低轨卫星星座的轻量化 LLM 推理框架，通过强化学习动态控制深度推理触发阈值（贡献一），结合星座分组的分布式 RAG 机制降低检索延迟（贡献二），并通过星-地定期同步保证知识库质量（贡献三）。

**可验证的实验指标**：
- 平均推理延迟（对比全量 LLM 调用）
- 决策质量（任务成功率 / 量化精度合规率）
- 快速路径命中率随时间的增长曲线
- 不同星间链路延迟下的性能
