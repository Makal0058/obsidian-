# 一、研究背景
## 1.1 前人做到哪一步
### 1.1.1 传统 Transformer 的计算能力受到固定结构限制

传统 Transformer 通过多层自注意力机制和前馈神经网络处理输入信息，每个输入 Token 对应一条残差流（Residual Stream），隐藏状态随着网络层数不断更新。然而，传统 Transformer 的计算深度和隐藏状态数量通常由模型结构预先确定。无论输入问题简单还是复杂，模型都需要按照固定的结构完成计算，难以根据问题的实际需求动态分配额外计算资源。

这一限制促使研究者探索如何在不单纯增加模型参数的情况下，提高 Transformer 的推理计算能力。
### 1.1.2 思维链通过增加 Token 扩展推理计算

思维链（Chain-of-Thought，CoT）通过让模型在给出最终答案之前生成中间推理步骤，使模型能够将复杂问题分解为多个子问题，并利用中间结果逐步完成推理。

已有研究进一步发现，即使不生成具有明确语义的推理文字，仅通过插入特殊的思考 Token，也可能增强 Transformer 的计算能力。

这说明，推理能力的提升不一定完全依赖自然语言表达，**增加用于内部计算的隐藏状态，同样可能提高模型处理复杂问题的能力。**
### 1.1.3 额外隐藏状态为隐空间计算提供了新的方向

在思维链研究的基础上，研究者提出了暂停 Token（Pause Tokens）等方法，通过在输入序列中添加额外的计算位置，使 Transformer 获得更多隐藏状态和计算资源。与显式思维链不同，这些额外隐藏状态不必对应自然语言推理步骤，可以直接在模型内部参与计算。

此外，已有自适应计算方法尝试通过循环计算、跳过网络层或者增加计算步骤，动态调整模型处理不同输入所需的计算量。这些研究表明，**Transformer 的计算资源不必完全固定，可以通过调整计算步骤或增加隐藏状态，为复杂输入分配更多计算。**
## 1.2 现有方法的主要问题
### 1.2.1 显式思维链依赖串行计算

传统思维链需要按照自回归方式逐个生成推理 Token。后续推理步骤依赖前面已经生成的 Token，因此难以直接并行生成全部推理过程。

同时，显式思维链通常依赖自然语言推理数据或推理阶段的额外计算，难以在普通语言模型预训练过程中直接学习这种推理方式。
### 1.2.2 现有额外隐藏状态方法缺乏动态分配能力

暂停 Token 等方法虽然能够增加内部计算资源，但通常需要提前确定额外 Token 的数量和插入位置。这种设计存在三个问题：

1. **缺乏输入自适应性**：不同输入的计算需求不同，但额外计算资源往往按照预先设定的方式分配。
2. **缺乏层级自适应性**：额外隐藏状态通常贯穿所有 Transformer 层，无法只在需要额外计算的中间层临时创建。
3. **依赖人工设计**：额外计算位置可能需要根据任务结构手动确定，难以直接推广到通用语言模型。

因此，增加隐藏状态虽然可以提供额外计算能力，但现有方法仍然难以解决应该在哪里增加计算、增加多少计算的问题。
### 1.2.3 缺乏仅依靠语言模型训练目标学习计算资源分配的机制

如果允许模型动态创建新的隐藏状态，还需要解决一个关键问题：**如何判断哪些隐藏状态值得保留、复制或删除**？简单复制隐藏状态虽然能够增加计算资源，但不一定能够产生有价值的额外计算。如果额外引入人工标注的推理步骤或专门的监督信号，又会提高训练复杂度，并削弱方法在普通语言模型预训练阶段的适用性。

因此，需要一种能够仅依靠标准语言模型训练目标，自主学习隐藏状态重要性和计算资源分配策略的方法。
## 1.3 本文的研究切入点
### 1.3.1 将额外计算建模为隐藏状态的动态分配问题

本文提出 Thoughtbubbles（思维气泡），将 Transformer 的额外计算能力建立在动态增加和删除残差流的基础上。其核心思想是：**不再预先固定所有额外隐藏状态，而是让模型根据隐藏状态的重要性，在网络内部自主决定哪些状态需要复制、保留或删除**。

对于需要更多计算的输入位置，模型可以通过复制残差流创建额外的并行计算分支；对于重要性较低的残差流，则可以将其删除，从而在有限的计算预算内重新分配资源。
### 1.3.2 通过可学习的分叉机制实现并行隐空间计算

本文在部分 Transformer 层之间引入分叉机制（Forking），为每条残差流计算两个分数：

1. **保留分数（Keep Score）**：衡量当前残差流继续存在的重要性。
2. **分叉分数（Fork Score）**：衡量是否值得复制当前残差流，创建新的计算分支。

模型将这些分数与历史累积分数结合，并在计算预算限制下，优先保留分数较高的残差流。新创建的残差流可以在后续 Transformer 层中参与并行计算，并通过注意力机制与其他允许访问的残差流交换信息。这样，模型就能够在网络内部形成临时扩展的隐藏状态集合，即思维气泡。
### 1.3.3 仅使用标准语言模型损失学习动态计算策略

本文没有为分叉决策引入额外的人工监督标签，而是通过累积分数调节注意力计算和残差更新。重要性较低的残差流，其参与注意力计算和状态更新的能力会受到抑制，使模型必须为真正有用的残差流分配较高分数。

经过这种设计，分叉机制能够在标准语言模型交叉熵损失的训练过程中得到优化。**最终，本文希望实现一种能够在预训练阶段自主学习计算资源分配，并在推理阶段根据输入需求执行额外并行隐空间计算的 Transformer 架构**。
# 二、创新点与贡献
## 2.1 提出动态分叉机制，实现隐空间并行计算
### 2.1.1 在 Transformer 内部动态创建和删除残差流

本文提出 Thoughtbubbles（思维气泡）架构，核心创新是在 Transformer 的部分网络层之间引入分叉机制（Forking），允许模型根据计算需求动态增加、保留或删除残差流（Residual Stream）。

传统 Transformer 的每个输入 Token 通常只对应一条残差流，并在各层之间持续更新。Thoughtbubbles 则允许一条残差流在中间层产生额外的计算分支。

具体过程如下：

1. **分叉（Fork）**：复制现有残差流，创建额外的隐藏状态。
2. **保留（Keep）**：让已有残差流继续参与后续计算。
3. **删除（Prune）**：移除重要性较低的额外残差流，释放计算预算。
4. **并行计算**：保留下来的残差流在后续 Transformer 层中同时参与计算，并通过注意力机制交互。

这样，模型能够在需要额外计算的位置形成临时扩展的隐藏状态集合，即思维气泡，而不必提前固定所有额外计算位置。与传统显式思维链不同，这些额外计算分支不需要生成自然语言 Token。

注：残差流（Residual Stream）就是 Transformer 中，某个 Token 的隐藏状态在不同网络层之间不断传递和更新所形成的计算路径。 它并不是一种新的神经网络模块，而是 Transformer 原本就有的结构。

1. 假设输入一句话：「小明喜欢苹果」，经过词嵌入后，每个 Token 都会得到一个隐藏状态向量。例如，「苹果」对应：$h_0=[0.2,0.5,0.8]$。这只是简化的三维向量，实际可能是几千维。接下来，这个隐藏状态会依次经过 Transformer 的各层。

2. **为什么叫「残差」流**

因为 Transformer 使用了残差连接（Residual Connection，残差连接）。例如，经过注意力模块后：$h_{\mathrm{new}}=h_{\mathrm{old}}+\mathrm{Attention}(\mathrm{LN}(h_{\mathrm{old}}))$。意思就是：新的隐藏状态 = 原来的隐藏状态 + 注意力模块计算出的更新量。而不是直接用注意力模块的输出替换原来的隐藏状态。这样，隐藏状态就能在原有信息的基础上不断更新，因此称为残差流。

3. **Thoughtbubbles 改进了什么**

传统 Transformer 中，每个 Token 通常对应一条残差流。Thoughtbubbles 则允许在某些网络层中，将一条残差流复制成多条：$h\to\begin{cases}h_A=h\\h_B=h+v\end{cases}$。其中 $v$ 是可学习的分叉向量。

这意味着，同一个 Token 可以拥有多条隐藏状态计算路径，经过后续 Transformer 层的并行计算。所以可以直接把「残差流」理解为「隐藏状态在 Transformer 各层之间持续更新的路径」。
### 2.1.2 通过可学习的分叉向量区分计算分支

如果只是简单复制隐藏状态，两个分支在相同条件下可能执行高度相似的计算。为此，本文在创建新分支时，向复制的隐藏状态添加一个可学习的分叉向量：$x_{\mathrm{fork}}^{(k)}=x^{(k)}+v_\theta^{(k)}$。其中：

- $x^{(k)}$：当前残差流的隐藏状态。
- $v_\theta^{(k)}$：第 $k$ 层可学习的分叉向量。
- $x_{\mathrm{fork}}^{(k)}$：新创建的分叉隐藏状态。

分叉后的隐藏状态与原始状态存在差异，因此可以在后续 Transformer 层中产生不同的计算结果。不过，本文没有专门设计分支多样性目标，也没有证明不同分支能够形成独立的推理思路。
## 2.2 提出基于重要性评分的动态计算资源分配机制
### 2.2.1 为每条残差流预测保留和分叉分数

本文设计了一个可学习的分叉决策函数，根据当前隐藏状态预测两个分数：$[p_{\mathrm{fork}},p_{\mathrm{keep}}]=\sigma(f_\theta(x))$。其中：

- $f_\theta$：可学习的分叉决策函数。
- $\sigma$：Sigmoid 激活函数。
- $p_{\mathrm{fork}}$：创建新分支的分数。
- $p_{\mathrm{keep}}$：保留当前残差流的分数。

这两个分数不是人工指定的，而是通过模型训练得到的。
### 2.2.2 引入累积分数衡量残差流的重要性

本文进一步引入累积分数（Cumulative Score），记录残差流经过多次分叉决策后所获得的重要性权重。每次分叉时，模型将新的分叉分数和保留分数分别乘以此前的累积分数：

$\hat p_{\mathrm{fork}}^{(k)}=p_{\mathrm{cum}}^{(k-1)}p_{\mathrm{fork}}^{(k)}$

$\hat p_{\mathrm{keep}}^{(k)}=p_{\mathrm{cum}}^{(k-1)}p_{\mathrm{keep}}^{(k)}$

这样，残差流的后续存活权重不仅取决于当前决策，还受到此前分叉历史的影响。
### 2.2.3 使用 Top-k 选择限制计算预算

由于不断复制隐藏状态会使计算量增加，本文设置最大残差流数量 $\kappa$，并使用 Top-k 机制决定保留哪些残差流。具体而言，模型将所有候选的保留分数和分叉分数放在一起排序，在预算范围内选择得分最高的候选。同时，本文通过强制保留每个输入 Token 的原始残差流，避免删除所有可用于预测该 Token 的状态。

**这一机制的创新在于，将动态计算资源分配转化为一个具有预算约束的残差流选择问题**。不过，这里的分数代表模型学习到的计算重要性，并不直接代表某条分支产生正确推理结果的概率。
## 2.3 提出基于累积分数的注意力与残差更新抑制机制
### 2.3.1 解决分叉决策缺少监督信号的问题

仅仅让模型预测分叉和保留分数，并不能保证它能够学会识别真正有价值的残差流。因为如果这些分数不影响模型的正常计算，语言模型损失就难以有效约束分叉决策。为解决这一问题，本文提出残差更新抑制机制（Residual Update Attenuation），将累积分数直接引入 Transformer 的计算过程。具体包括：

1. **注意力调节**：根据累积分数调整注意力计算，使低分残差流对其他状态的影响受到抑制。
2. **残差更新调节**：使用累积分数缩放注意力输出和前馈网络输出，限制低分残差流的状态更新幅度。
### 2.3.2 使分叉决策能够通过语言模型损失学习

通过上述设计，分叉分数与模型最终的预测表现建立了联系。如果某条残差流对预测任务非常重要，那么持续降低它的累积分数可能损害模型表现。因此，模型在优化语言模型损失时，会受到训练信号的驱动，为有用的残差流分配较高分数。

**这一设计使模型能够仅使用标准语言模型交叉熵损失学习分叉策略，而不需要额外提供哪些隐藏状态应该复制或删除的监督标签**。需要注意，本文采用的是通过分数调节计算来间接学习分叉决策的方法，并非直接为每次离散的 Top-k 选择提供监督标签。
## 2.4 设计适应动态分叉的位置编码机制
### 2.4.1 对旋转位置编码进行部分旋转

Thoughtbubbles 在网络内部动态增加残差流后，需要处理新分支的位置表示。本文对旋转位置编码（RoPE）进行了调整，采用部分旋转（Partial Rotation）机制，使分叉状态的位置表示与原始 Token 及其分叉数量相适应。分叉次数越多，相关分支在位置表示中的相对距离越近。

这一设计使动态增加的残差流能够融入原有 Transformer 的注意力计算，同时尽量保留合理的位置关系。
## 2.5 提出多残差流输出聚合机制
### 2.5.1 根据累积分数加权合并输出概率

经过多层计算后，同一个输入 Token 可能对应多条残差流。由于语言模型最终需要为每个输入位置产生一个预测分布，本文提出基于累积分数的输出聚合机制。具体而言：

1. 将每条残差流分别映射为词表上的预测概率分布。
2. 使用对应的累积分数作为权重。
3. 对这些概率分布进行加权平均，形成最终预测分布。

这种方法使多个隐藏状态能够共同参与最终 Token 预测。
### 2.5.2 使用隐藏状态加权平均降低计算成本

由于分别计算多个完整词表概率分布会带来较大的计算和显存开销，本文还提出了更高效的近似方法：**先根据累积分数对多条残差流的隐藏状态进行加权平均，再将聚合后的隐藏状态映射为最终预测分布**。在最大的 1.9B 参数模型中，作者采用了这一近似方法，以降低输出聚合的计算开销。

需要注意，本文的输出聚合主要面向同一输入 Token 的多个残差流，并不是专门针对不同推理答案设计的候选验证或投票机制。
## 2.6 实验验证动态并行隐空间计算的有效性
### 2.6.1 验证不同模型规模下的性能提升

本文在 150M 至 1.9B 参数规模的模型上开展实验，并与标准 Transformer、固定复制隐藏状态的方法进行比较。实验表明，Thoughtbubbles 能够在不同规模下改善语言模型的困惑度，并在多项零样本评测中取得具有竞争力的结果。其中，在 1.9B 参数规模下：

- Thoughtbubbles 训练 20B Token 后，困惑度达到 12.68。
- 标准 Transformer 训练 40B Token 后，困惑度为 15.03。
- GSM8K 准确率分别为 31.50% 和 31.46%。

这表明，动态分配额外残差流能够提高模型对训练数据的利用效率。不过，训练 Token 数量减半不等于总计算量减半，因为额外残差流本身也会增加计算成本。
### 2.6.2 发现模型能够自主分配更多计算资源给高不确定性区域

本文分析了残差流分叉数量与输出预测熵之间的关系。结果发现：

- 模型能够在没有额外分叉监督的条件下，自主学习非均匀的计算资源分配策略。
- 预测不确定性较高的区域通常获得更多计算分支。
- 分叉数量与预测熵之间并非简单的线性关系，在最高不确定性区域，计算资源分配反而可能减少。

作者认为，这可能是因为中等不确定性区域往往更容易通过额外计算获得收益，而最高不确定性区域未必能够通过增加计算解决。**这一结果支持了本文的核心观点：模型可以仅依靠语言模型训练目标，学习根据输入内容动态分配额外的隐空间计算资源**。

但需要区分：这一实验验证的是计算资源分配的自适应性，并没有直接验证多个分叉是否形成了不同的推理策略。
## 2.7 本文的核心贡献总结

本文的主要贡献可以归纳为三个方面：

1. **架构创新**：提出 Thoughtbubbles，使 Transformer 能够在内部动态创建、保留和删除额外残差流，实现具有预算约束的并行隐空间计算。
2. **训练机制创新**：将累积分数用于注意力计算和残差更新，使动态计算资源分配能够仅依靠标准语言模型损失进行学习，不需要额外的分叉监督信号。
3. **实验贡献**：在 150M 至 1.9B 参数规模上验证方法的有效性，展示了动态并行计算在语言建模、零样本评测和计算资源自适应分配方面的优势。

总体而言，**本文主要解决的是 Transformer 如何动态增加和分配内部计算资源的问题，而不是如何让多个隐空间候选形成不同推理思路并进行协作的问题。**

| 模型规模 | Transformer 层数 | 隐藏维度 |
| --- | --- | --- |
| 150M | 16 | 768 |
| 319M | 24 | 1024 |
| 772M | 36 | 1280 |
| 1.9B | 36 | 2048 |
所有模型均采用仅解码器（Decoder-only）架构，使用标准语言模型交叉熵损失进行训练。分叉机制设置在第 3、7、11 层之前，计算预算主要采用两种配置：

- $\kappa=2L$：残差流总数最多为原始 Token 数量的 2 倍。
- $\kappa=4L$：残差流总数最多为原始 Token 数量的 4 倍。

其中，$L$ 表示原始输入序列长度，$\kappa$ 表示允许保留的最大残差流数量。
### 3.1.2 实验数据集

本文使用三类主要训练数据：

1. **OpenWebText**：网页文本语料，用于验证通用语言建模能力。
2. **peS2o**：学术论文文本语料，用于验证科学文本建模能力。
3. **FineWeb**：高质量网页语料，用于大规模预训练。

150M、319M 和 772M 模型分别在 OpenWebText 和 peS2o 上训练 25 亿 Token。1.9B 模型采用两阶段训练：

- **预训练阶段**：使用 70% FineWeb 和 30% peS2o 构成的混合数据，最多训练 400 亿 Token，并保存 200 亿 Token 时的检查点。
- **中期训练阶段**：额外使用 20 亿 Token 的混合数据，其中包含 40% GSM8K-aug 数学推理语料，以及 MMLU、SmolTalk 和预训练语料。

因此，GSM8K 实验并非完全没有接触过数学推理数据，只是不需要为 Thoughtbubbles 的分叉决策提供额外监督标签。
### 3.1.3 对比方法

本文设置三类主要方法：

1. **标准 Transformer（Baseline）**：采用类似 GPT-2 的架构，不增加额外残差流。
2. **固定复制方法（Copy-3、Copy-5）**：在输入阶段直接将残差流复制为多份，使它们能够通过注意力交互，但不根据输入内容动态分叉。
3. **Thoughtbubbles**：通过可学习的分叉分数，动态决定残差流的创建、保留和删除。

其中，固定复制方法是重要的对照组，因为它能够检验性能提升究竟来自简单增加隐藏状态，还是来自动态分配计算资源。
### 3.1.4 评估指标

本文主要使用以下指标：

- **困惑度（Perplexity）**：衡量语言模型预测文本的能力，越低越好。
- **LAMBADA**：评估利用上下文信息预测目标词的能力。
- **HellaSwag**：评估常识理解和合理续写选择能力。
- **BLiMP**：评估语法知识。
- **PIQA**：评估物理常识推理能力。
- **ARC-Easy / ARC-Challenge**：评估科学知识和基础推理能力。
- **GSM8K**：评估数学应用题的求解准确率。

这些指标主要用于检验语言建模和下游任务性能，并不能直接衡量多个隐藏状态是否产生了独立推理思路。
## 3.2 大规模实验：动态分叉能否改善模型性能
### 3.2.1 1.9B 模型的实验结果

论文表 1 比较了参数量相同的标准 Transformer 与 Thoughtbubbles。

| 指标 | 标准 Transformer 40B | Thoughtbubbles 20B | Thoughtbubbles 40B |
| --- | --- | --- | --- |
| 困惑度 ↓ | 15.03 | 12.68 | **12.09** |
| BLiMP ↑ | 77.49 | **78.54** | 78.41 |
| HellaSwag ↑ | 47.29 | 50.04 | **54.16** |
| PIQA ↑ | 71.79 | **73.42** | 73.00 |
| ARC-Easy ↑ | 38.31 | 39.72 | **42.53** |
| ARC-Challenge ↑ | 26.17 | 24.50 | **29.53** |
| LAMBADA ↑ | 39.15 | 39.32 | **43.91** |
| GSM8K ↑ | 31.46 | 31.50 | **32.10** |

其中，20B 和 40B 表示预训练 Token 数量。**实验结果说明：**

1. Thoughtbubbles 在只使用一半预训练 Token 的情况下，困惑度就从基线的 15.03 降至 12.68，说明其语言建模能力明显改善。
2. 在相同预训练 Token 数量下，Thoughtbubbles 的困惑度进一步降至 12.09，表明动态残差流机制具有持续收益。
3. HellaSwag、LAMBADA 等任务也取得明显提升，说明增加内部并行计算能够改善部分语言理解能力。
4. GSM8K 准确率从 31.46% 提升至 32.10%，仅提高 0.64 个百分点，数学推理收益相对有限。
5. 20B 配置在 ARC-Challenge 上只有 24.50%，低于基线的 26.17%，说明使用更少训练数据并不能保证所有任务都获得提升。

**结论：Thoughtbubbles 对语言建模能力的提升比较明确，但对数学推理能力的改善远小于困惑度改善，尚不能证明该架构显著增强了复杂多步推理能力。**
## 3.3 模型规模与计算预算实验
### 3.3.1 不同模型规模下的性能变化

论文表 2 在 150M、319M、772M 三种规模下进行对比。以 OpenWebText 数据集为例：

| 模型规模 | 标准 Transformer | Thoughtbubbles 2L | Thoughtbubbles 4L |
| --- | --- | --- | --- |
| 150M | 24.51 | 23.78 | 23.19 |
| 319M | 21.56 | 20.55 | 20.23 |
| 772M | 21.22 | 20.19 | 19.74 |

表中数值为困惑度，越低越好。**实验结果说明：**

1. 在三种模型规模下，Thoughtbubbles 均取得比标准 Transformer 更低的困惑度。
2. 在相同模型规模下，将残差流预算从 2L 提高到 4L，能够进一步降低困惑度。
3. 319M Thoughtbubbles 在 4L 配置下的困惑度为 20.23，优于 772M 标准 Transformer 的 21.22。

这表明，增加动态并行计算可以在一定程度上弥补模型参数规模较小带来的性能差距。不过，在 peS2o 数据集上的 BLiMP、PIQA 等部分指标中，Thoughtbubbles 并非始终优于所有基线。
### 3.3.2 动态分叉与固定复制的比较

论文进一步比较了动态分叉和固定复制隐藏状态的方法。以 772M 模型在 OpenWebText 上的困惑度为例：

| 方法 | 困惑度 ↓ |
| --- | --- |
| 标准 Transformer | 21.22 |
| Copy-3 | 21.20 |
| Copy-5 | 20.90 |
| Thoughtbubbles（2L） | 20.19 |
| Thoughtbubbles（4L） | **19.74** |

固定复制隐藏状态虽然能够增加计算资源，但性能改善有限。相比之下，Thoughtbubbles 能够根据模型学习到的重要性分数，将额外计算资源分配给特定输入位置，因此取得更好的结果。

**结论：实验支持动态计算资源分配比简单增加固定隐藏状态更有效。**

但这并不能说明动态分叉后的隐藏状态形成了不同的推理策略，只能说明这种额外计算方式更有利于语言建模。
## 3.4 隐藏状态分叉行为分析
### 3.4.1 分叉状态是否真正参与计算

论文图 4 分析了原始残差流与额外分叉之间的注意力分配。实验发现：

1. 原始 Token 对自身分叉状态的注意力权重明显高于对普通其他 Token 的注意力权重。
2. 分叉状态之间也存在注意力交互。
3. 由于分叉状态被插入到原始 Token 左侧，并受到因果注意力约束，原始 Token 可以读取分叉状态，但分叉状态不能直接读取其右侧的原始 Token。

这些现象说明，新增的残差流不是完全被模型忽略的冗余状态，而是参与了后续的信息处理。**结论：分叉状态确实能够通过注意力机制影响原始残差流的计算**。

但注意力权重较高并不等于分叉承担了独立的推理功能，也不能仅凭注意力分析证明不同分叉之间存在有效的推理协作。
### 3.4.2 计算资源是否集中在高不确定性区域

论文图 5 分析了分叉数量与预测熵之间的关系。预测熵越高，通常表示模型对下一个 Token 的预测越不确定。实验发现：

1. 模型能够在没有显式分叉监督的情况下，学习非均匀的计算资源分配。
2. 与低不确定性区域相比，中等至较高不确定性的区域通常获得更多计算分支。
3. 当预测熵达到最高水平时，分叉数量反而可能下降，整体表现出非单调关系。

作者推测，中等不确定性区域可能更容易从额外计算中获益，而最高不确定性区域的预测困难未必能够通过增加计算解决。论文附录还利用 CLUTTR 关系任务进行定性分析，发现模型倾向于在实体指代、查询边界等位置增加分叉。

**结论：模型能够学习具有一定内容适应性的计算资源分配策略，但预测熵与计算价值之间并不存在简单的一一对应关系。**

需要注意，这些实验并没有证明模型能够准确识别所有真正需要复杂推理的位置，也没有直接验证额外计算是否提高了这些位置的推理正确率。
## 3.5 消融实验与计算效率分析
### 3.5.1 输出聚合机制的消融实验

论文表 6 比较了使用多个残差流聚合输出，与只保留最右侧原始残差流输出的区别。

| 方法 | 验证损失 ↓ |
| --- | --- |
| 标准 Transformer | 3.27 |
| Thoughtbubbles（输出聚合） | **3.17** |
| Thoughtbubbles（仅原始残差流输出） | 3.21 |
实验发现，使用多个残差流共同参与输出预测，能够进一步降低验证损失。但去除输出聚合后，模型仍然优于标准 Transformer。**结论：输出聚合具有一定价值，但不是性能提升的唯一来源**。
### 3.5.2 注意力分数调节机制的消融实验

论文表 7 移除了基于累积分数的注意力调节机制。

| 方法 | 验证损失 ↓ |
| --- | --- |
| 标准 Transformer | 3.27 |
| Thoughtbubbles（完整方法） | **3.17** |
| Thoughtbubbles（移除注意力分数调节） | 3.90 |
移除该机制后，验证损失从 3.17 上升至 3.90，甚至明显差于标准 Transformer。作者认为，如果累积分数不参与实际计算，模型就难以学习有意义的分叉选择，导致保留和分叉决策失去有效依据。

**结论：将重要性分数与 Transformer 实际计算过程联系起来，是动态分叉机制有效工作的关键**。这一实验也表明，仅仅添加一个预测分叉分数的小网络，并不能保证模型学会合理分配计算资源。
### 3.5.3 增加分叉层数的实验

论文表 8 比较了原始分叉层设置和进一步增加后续分叉层的方案。

| 方法 | 困惑度 ↓ |
| --- | --- |
| 原始分叉设置 | 29.84 |
| 增加后续分叉层 | **28.02** |
增加分叉层数能够进一步改善困惑度，但作者认为收益有限，并指出硬 Top-k 选择可能使早期高分残差流在后续被删除，阻断部分训练梯度。这说明分叉次数和分叉位置的增加并不一定持续带来稳定收益。
### 3.5.4 实际计算开销

论文附录表 5 在 H100 GPU 上测试了 1.9B 模型的前向与反向传播耗时。

| 方法 | 耗时 |
| --- | --- |
| 标准 Transformer | 234 ms |
| Thoughtbubbles（2L） | 327 ms |
| 标准 Transformer（输入长度 2L） | 380 ms |
**实验结果说明：**

1. Thoughtbubbles 比原始 Transformer 慢约 40%，因此动态分叉并非没有计算成本。
2. Thoughtbubbles 比直接将标准 Transformer 输入长度翻倍的方案更快。
3. 结合前面的训练结果，作者认为 Thoughtbubbles 具有一定的实际训练效率优势。

但这一实验测量的是特定硬件和配置下的单次前向、反向传播耗时，不能直接说明所有模型规模和部署条件下的端到端推理效率。
### 3.5.5 自回归生成中的计算预算问题

论文图 6 比较了不同推理预算分配方式。

| 方法 | 困惑度 ↓ |
| --- | --- |
| 分块前向计算 | **20.97** |
| 自回归生成：固定预算 | 23.10 |
| 自回归生成：动态预算 | 21.18 |
| 标准 Transformer | 22.15 |
固定分叉预算会造成训练与推理之间的分布偏移，使模型性能下降。将分叉预算按照当前输入长度动态缩放后，困惑度从 23.10 降至 21.18，接近分块前向计算的结果。

**结论：动态分叉不仅需要学习隐藏状态的重要性，还需要正确处理训练与自回归推理时计算预算的变化。**
## 3.6 研究局限性
### 3.6.1 没有证明分叉隐藏状态形成独立推理思路

本文虽然创建了多个并行残差流，但没有对不同分支进行明确的功能分工。

论文没有验证：

1. 不同分叉是否学习到不同的推理策略。
2. 不同分叉是否具有互补的中间推理结果。
3. 分叉之间的信息交互是否能够纠正错误推理。
4. 多个分叉是否能够探索不同答案，并通过协作得到更可靠的结果。

因此，不能将 Thoughtbubbles 的动态分叉直接等同于多候选隐空间推理。
### 3.6.2 对复杂推理能力的验证仍然有限

本文主要使用困惑度及常规零样本任务评估模型性能。

虽然包含 GSM8K 和 ARC-Challenge，但没有系统测试推理深度、候选思路多样性、长链推理稳定性等问题。

特别是在 1.9B 模型上，GSM8K 准确率仅由 31.46% 提升至 32.10%。

这说明模型在语言建模方面的性能提升，并没有等比例转化为数学推理准确率的提升。
### 3.6.3 缺乏分叉计算过程的功能性验证

本文通过注意力分析、预测熵分析以及分叉位置可视化，观察模型如何分配计算资源。但这些分析主要是相关性证据。

例如，某个 Token 获得更多分叉，不一定意味着它真正需要更多推理步骤；两个分叉之间存在注意力联系，也不代表它们交换了有效的推理信息。

因此，仍然缺乏通过删除、替换、交换分叉状态等干预实验，验证不同分叉具体承担何种计算功能的证据。
### 3.6.4 分叉选择可能造成梯度传播问题

本文依赖硬 Top-k 机制决定哪些残差流继续存在。这种离散选择可能导致：

- 部分有价值的残差流被提前删除。
- 被删除分支难以获得后续任务损失提供的训练信号。
- 增加分叉层数后，训练优化更加困难。

作者在增加分叉层数的实验中讨论了这一问题，但没有系统验证如何彻底解决。
### 3.6.5 计算成本与模型规模仍有限制

虽然 Thoughtbubbles 能够以较少训练 Token 取得更低困惑度，但每个 Token 可能对应多条残差流，因此仍然需要额外的计算和显存。此外，本文最大实验规模为 1.9B 参数，尚未通过实验确定该机制在更大参数规模、长上下文和复杂生成任务中的收益。

论文也没有针对不同分叉策略提供充分的多随机种子统计分析，因此部分较小的性能差异仍需要进一步验证。
## 3.7 实验总体结论

本文实验主要支持以下三个结论：

1. **动态分叉确实能够改善语言建模性能。** 在不同数据集和模型规模下，Thoughtbubbles 通常能够获得更低的困惑度，并且优于简单固定复制残差流的方法。
2. **Transformer 可以仅依靠标准语言模型损失学习计算资源分配。** 模型能够自主调整分叉位置和数量，并倾向于在具有一定预测不确定性的区域投入更多计算。
3. **额外隐藏状态能够参与有效计算，但不意味着形成独立推理思路。** 注意力分析和消融实验支持分叉状态确实影响模型预测，却没有证明不同分支形成了独立、互补或可相互验证的推理策略。

**因此，Thoughtbubbles 的实验主要证明了动态并行隐空间计算能够提高 Transformer 的计算资源利用效果和语言建模能力，而不是证明多候选隐空间推理已经得到解决。**

对于多候选隐空间推理研究而言，这篇论文更适合作为动态计算资源分配和隐藏状态分叉机制的参考，而不是直接作为候选推理通信与协作机制已经有效的证据。
