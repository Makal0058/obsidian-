# 内嵌推理模块：实验设计与创新核查

版本：2026-10-13。状态：研究设计，未实现、未训练、未获得实验结果。文中数值为建议起始配置或预注册决策标准，不是已验证最优值。本轮核查覆盖直接近邻，不能作为穷尽查新或首创性证明。

## 1. 完整设想与研究问题

用户已明确的要求：修改 Transformer 架构；增加参与前向计算和反向传播的新模块；使模块参与隐状态演化和动态显式／隐式推理；采用 SIM-CoT 式逐步监督和强化学习；先冻结主干训练新模块，再冻结新模块训练主干，最后联合优化。实际效率与准确率通过实验判断。

本文新增的工程选择：先在最后一个 Block 的 FFN 残差之后、最终归一化之前插入一个模块；模块持有少量工作状态，并能在同一文本位置循环。第一版只修改一个位置，不同时研究每层独立控制、MoE 或多候选通信。这些选择是为了使实验可归因，不是用户已经指定的结构。

主问题：经过逐步监督的工作状态，能否支持有用的内部计算，并让模型根据不同计算动作的预期收益，在给定预算下选择继续隐式计算、生成显式推理或开始回答？

三个可证伪假设：

- H1 表示计算：在相同主干、数据和推理预算下，循环状态更新优于一次性残差适配；后续状态更新确实影响答案。
- H2 决策：状态相关的动态策略优于调好预算的固定、随机和熵策略；优势来自决策时机，而非多执行计算。
- H3 协同训练：新模块→主干→联合的训练流程，在等训练计算量下优于新模块→直接联合；阶段 2 不是默认必要。

H1、H2、H3 不能相互替代。只通过 H1 是模块结果；只通过 H2 可能是控制策略结果；H3 只能支持训练流程贡献。

## 2. 第一版架构：最后一个 Block 内的有状态子层

主干参数记为 θ，新模块参数分成状态更新 φ、读写接口 ω、策略 ψ；训练用辅助解码器参数 ξ。新模块的完整参数集合是 Φ={φ,ω,ψ}。

设主干最后一个 Block 的 FFN 残差输出为 h_t∈R^d，文本前缀为 x₁:ₜ。h_t 在此处尚未经过最终归一化和 LM head。插入点要以具体模型源码确认，不能重复套最终归一化。

工作状态 Z∈R^(m×r)，默认 m=4、r=256、注意力头数 4、共享更新块 1 个、FFN 中间维度 1024。m 个槽只是工作空间，不称为 m 条独立推理路线，也不预设各槽具有不同语义。

### 2.1 读取与初始化

主干产生的可见前缀表示 H_t=[h₁,…,hₜ] 经线性映射成为模块自己的上下文 K^R_t、V^R_t。每增加一个文本位置才为它追加一次投影。

Z₀[j]=LN(W_init h_prompt+e_j)，其中 e_j 是工作槽的可训练偏置。Z 只在新问题开始时初始化，跨显式片段保留。

模块只能读取当前已经出现的文本前缀。训练时被改成 Latent 的参考步骤必须从主干可见文本中删除，不能只是把标签设成 -100 后仍把该步骤喂给主干。

### 2.2 一次 Latent 动作

令 k 表示内部循环次数，t 表示文本位置：

```text
Z ← Z + SelfAttention(LN(Z))
Z ← Z + CrossAttention(LN(Z), K_R[:t], V_R[:t])
Z ← Z + FFN_R(LN(Z))
k ← k + 1
```

同一组参数被反复使用。一次动作只增加 k，不增加文本位置 t、不执行整套主干、不追加主干 KV、不运行辅助解码器。上下文投影、内部注意力和状态更新仍需算入 FLOPs。

### 2.3 写回与预测

```text
z_bar = mean(Z, slots)
g = sigmoid(G(concat(W_h h_t, z_bar)))
h_t_out = h_t + g * W_out z_bar
logits = LM_head(final_norm(h_t_out))
```

W_out 从 r 投影回 d，g 第一版用标量；以小但非零的残差尺度初始化，避免同时把读写路径和门控全部置零造成初期无有效梯度。LM head 和嵌入沿用主干，是否绑定遵循原模型实现。

这个子层实际改变预测使用的隐藏状态。主干原有的最后一层注意力 KV 在写回之前已经计算，因此仅修改当前输出不会使历史 KV 失效。这是选择末层插入的工程原因，不代表末层必然最优。

局限：纯 Latent 期间重用主干提供的上下文表示，更新能力主要来自小模块；显式文本生成前的更早主干层不能直接读取当前 Z。若容量不足，后续再比较“最后两层共享循环”或“向更早层写回”，不能先假定小模块能替代完整主干推理。

### 2.4 三个动作的严格定义

策略输入为 mean(Z)、W_h h_t、最近一次状态变化范数、上一动作和剩余预算。基础版本不输入词表熵；熵作为可选特征消融，计算开销计入总成本。

| 动作 | 操作 | 状态与缓存 |
|---|---|---|
| L：Latent | 运行一次共享更新块 | 更新 Z；文本位置、主干 KV 不变 |
| E：Explicit | 自回归生成一个推理片段，遇换行结束，最多 32 个 token | 每个 token 正常更新主干 KV 与模块上下文投影；保留 Z |
| A：Answer | 添加统一的答案前缀并生成最终答案，最多 64 个 token | 退出模式决策；保留 Z 供每个答案 token 写回；正常更新文本缓存 |

显式片段每个 token 都使用写回接口，但不自动多运行一次循环更新；否则一次 E 会暗含许多 L，无法解释成本。达到 32 token 截断后允许下次 E 继续该片段，记录截断率。统一答案前缀例如 `\nAnswer: `，所有方法都使用并计入成本。它是执行协议，不是额外正确答案信息。

每题上限：16 次 L、8 次 E、24 次模式决策；先达到预算或次数上限就强制进入 A。强制动作不计策略梯度，另报强制回答率。训练和推理使用同一约束。若经常触顶，应检查策略与预算，而不能把硬上限效果归功于学会停止。

```python
# 设计伪代码，不是已实现的运行入口
state = prefill_question(question)
Z = initialize_workspace(state.last_hidden)
while within_reasoning_budget(state):
    action = policy(Z, state.last_hidden, state.budget)
    if action == LATENT:
        Z = latent_update(Z, state.context_memory)
        state.charge_latent_cost()
    elif action == EXPLICIT:
        state = decode_chunk(state, Z, max_tokens=32)
    else:
        break
answer = decode_answer(state, Z, max_tokens=64)
```

### 2.5 梯度与缓存的实现要求

- SFT 中模块连续更新通过展开的计算图反传。主干冻结只意味着 θ 不更新。
- 阶段 2 冻结 Φ 后，梯度必须能穿过新模块到达 θ；不能整体用 no_grad() 包住它。
- 该末层版本的主干输入不含 Z，因此冻结主干时可以缓存或无梯度计算其前缀表示；若以后改成更早层注入 Z，此优化不再直接成立。
- 联合训练时，缓存应来自当前参数的可微重算；不能把推理引擎返回的 detached KV/hidden 当成可反传缓存。
- 训练重放：按轨迹里实际生成的 token 和动作重新计算主干表示，再按动作位置展开 Z。主干可对完整可见序列做一次因果前向，但每次 L 只能访问当时的前缀切片。
- 主干 RoPE 位置只随真实 token 增长；内部循环无需伪造新文本位置。模块上下文表示已含位置信息，第一版不另设每轮独立位置向量。

## 3. 数据、任务和模型

### 3.1 基础模型与共同起点

工程试验采用 Qwen/Qwen3-0.6B，正结果再扩展至同系列 1.7B，并最终补一个不同模型家族验证。使用模型卡支持的 enable_thinking=False，统一以正文中的显式步骤训练各方法，避免模型原生思考开关成为额外变量。关闭原生思考模板不等于禁止训练正文形式的 CoT。[官方模型卡](https://huggingface.co/Qwen/Qwen3-0.6B)

所有对照共享同一个 S0 显式 CoT 检查点。S0 在相同训练集上做 1 epoch LoRA SFT，并合并权重后另存。不允许完整方法从更强的 CoT 检查点开始而让基线使用原始模型。

小模型上的成功仅支持机制可行；失败也可能来自容量和优化。不能从一个 0.6B 结果推断所有 LLM。

### 3.2 两条独立实验线

| 线 | 数据 | 建议划分 | 检验目标 |
|---|---|---|---|
| 受控机制线 | 自动生成的变量赋值／算术程序执行 | 训练 20,000；验证 2,000；同分布测试 2,000；长链测试 2,000；新组合测试 2,000 | 状态更新、步骤监督、长度泛化与干预 |
| 自然语言线 | GSM8K 原始训练集、官方测试；SVAMP 外部测试 | GSM8K 原始训练集中固定留出 1,000，其余训练；官方 test 保持独立；SVAMP 只测试 | 真实文字题上的准确率—成本收益 |

官方数据来源：[GSM8K](https://github.com/openai/grade-school-math)、[SVAMP](https://github.com/arkilpatel/SVAMP)。具体样本数以下载后 manifest 为准，记录版本和哈希。

受控任务：输入包含初值与多条赋值规则，例如 `a=3; b=a+4; c=2*b; d=c-5; 求 d`；程序执行器产生每个中间状态与精确答案。训练依赖链长 2–6，长链测试 8–12；运算限制在可精确验证范围，除法必须整除，不让数字位数变化成为唯一难度因素。另设训练中未见的运算符组合／依赖图模板。按程序模板族和规范化表达式切分后再采样常数，检查跨集合去重，不仅按随机种子切分。

主结果先分别训练两个任务，避免合成任务的数据量掩盖 GSM8K 收益；迁移实验单独报告。

GSM8K 步骤按原有行边界和算式边界确定，长于 32 token 的步骤按固定规则分成连续片段，并标记其不一定对应一个完整逻辑步骤。所有方法使用相同预处理。先人工抽查 100 例切分与答案解析；不额外生成未经验证的推理链。前缀裁剪不得丢掉最终答案或改变题意，超长样本的排除规则与数量预先记录。

训练／验证／测试按原题分组。如果后续使用 GSM8K-Aug，必须让同一原题的所有增强样本属于同一划分，并将增强训练作为独立规模实验。

### 3.3 逐步监督如何避免信息泄露

训练时对参考步骤采样显式／隐式掩码。被隐式替代的第 j 步 s_j 不出现在主干文本中；执行一次 L，得到 Z_j，再用辅助解码器 D_ξ(Z_j,s_j,<i) 预测 s_j,i。解码器能见到 Z_j 和当前步骤已经生成的 token，不能读取当前步骤完整答案、之后的步骤或整条正确 CoT。

辅助解码器起始配置：2 层因果 decoder、宽度 256、4 头、交叉注意力读取 4 个槽；使用主模型 tokenizer，嵌入／输出投影的共享方式固定并记录参数量。训练与推理成本分开计量，不能因为推理移除就隐去训练成本。

按 token 平均的步骤 CE 促进可解码语义，但不能证明模型真正使用了这些语义。必须加入打乱 Z 后的重建测试，以及第 7 节的答案干预。

## 4. 用户要求的三阶段训练：具体版本

先做 S0 共同起点。以下阶段预算是第一轮起始值，各数据线分别使用，不先做大规模超参数搜索。

### 阶段 1：冻结主干，训练新增模块

1A 状态预热：冻结 θ 和策略 ψ，训练 φ、ω、ξ。对训练轨迹随机把一部分步骤替换为 L；隐式比例按 0.25→0.50→0.75 递增。随机掩码用于分支训练，不能当作正确策略标签训练 ψ。

L_sup = L_answer + L_explicit + λ_step L_step。

每项先按自身有效 token 平均；起始 λ_step=0.5。GSM8K 跑 2 epochs，合成线 1 epoch，按验证准确率及实际成本保存检查点。记录每种掩码下的收益，不能只检查 teacher-forcing CE。

1B 策略预热与 RL：暂时冻结 φ、ω、ξ，只训练新增策略 ψ，仍属于“主干冻结、训练新模块”阶段。

- 从训练集 512 个前缀状态出发，分别尝试 L、E、A，每个分支 2 次续写，得到粗略结果。它们用于策略预热；估计噪声很大时使用软标签或仅保留显著分开的动作，不能当成可靠 oracle。
- 分支后采用共同的预算与固定续写策略。用最终正确性减成本选择动作，绝不把熵阈值直接当唯一标签。
- 随后执行 200 个新鲜 on-policy 更新，每次 4 道题、每题 4 条轨迹，采用 RLOO 基线。阶段 1B 只对模式动作计算策略梯度，文本生成分布固定。
- 熵奖励从 0.01 线性衰减到 0.001。它鼓励早期探索，不永久强制三种动作均匀出现。

先使用 λ_cost=0.05 做工程验证；正式曲线训练 λ_cost∈{0,0.02,0.05,0.1}，候选范围只在验证集调整。

### 阶段 2：冻结新增模块，训练主干

冻结 φ、ω、ψ、ξ，只训练主干 LoRA，rank=16、alpha=32、dropout=0；作用于主干注意力与 FFN 的线性层，按模型实际模块名绑定并记录。GSM8K 跑 1 epoch，合成线 1 epoch。

为了先隔离“主干适应新模块”的效果，阶段 2 采用与 1A 相同的已知混合轨迹和监督目标，不同时启动一个新的离散策略优化。步骤解码器冻结但仍允许梯度经它传到 Z 与主干。

每 100 次更新在固定验证子集上监测：最终准确率、L/E/A 分布、平均成本、强制停止率、冻结策略相对于阶段 1 末尾的变化。冻结 ψ 不代表策略输出不变，因为输入 h_t 改变了。保存验证上最佳检查点，退化时降低学习率并回滚。

### 阶段 3：联合优化

同时训练 Φ 和主干 LoRA，ξ 只由监督辅助损失更新。不要把辅助解码器梯度误称为来自 RL。

每个联合更新使用：4 道新采样训练题×4 条新鲜轨迹的 RL 项，另加 8 条训练题的混合轨迹 SFT 项。起始跑 300 次更新：

L_joint = L_RL + 0.2 (L_answer+L_explicit) + 0.1 L_step。

所有项的归一化方式固定。监督数据与 RL 数据均来自训练划分，测试答案不参与训练或预算选择。每个 rollout 只用于一次参数更新，第一版避免多轮复用旧隐状态。

初始学习率建议：

| 阶段 | 新模块 | 主干 LoRA | 辅助 decoder |
|---|---:|---:|---:|
| 1A | 1e-4 | 冻结 | 1e-4 |
| 1B | 策略 5e-5，其余冻结 | 冻结 | 冻结 |
| 2 | 冻结 | 1e-5 | 冻结 |
| 3 | 1e-5 | 2e-6 | 1e-5，仅监督项 |

AdamW、weight decay=0.01、梯度裁剪 1.0、BF16（设备支持时）、SFT 有效 batch=32、microbatch=1、梯度累积。warmup=5%。初始上限并非最优值，先监测 100 次更新的稳定性和资源占用，再估计总训练时间。

### 4.1 RL 奖励与概率，避免实现歧义

每条轨迹奖励：R=1[答案正确]−λ_cost·C_total/C_ref。C_ref 是共同 S0 在训练校准集上的中位总 FLOPs，之后固定。C_total 包含 prefill、推理文本、Latent、策略、读写接口、答案生成；不把一个 L 和一个 token 视为同成本。推理阶段的辅助 decoder 成本为零，但训练成本必须另报。

初版不加切换惩罚，避免它替代模式收益学习；如出现频繁切换导致延迟，再作为独立消融加入。

阶段 3 的轨迹随机性来自模式动作和实际生成 token。联合 log-probability 为：

log p(τ|x)=Σ决策 log π_ψ(a|state)+Σ采样文本位置 log p_(θ,Φ)(token|prefix,Z)。

确定性 Z 更新不虚构为有概率密度的采样动作，但后续 log-probability 的梯度必须穿过 Z。RLOO 优势 A_i=R_i−mean(R_j,j≠i)，在反传中作为常数。L_RL=−mean_i[A_i·log p(τ_i|x)]−β_H·H_policy。

对阶段 1B，因为执行器与文本分布冻结，只需要模式 log-probability 项；阶段 3 同时纳入模式和文本项。固定插入的答案前缀、预算触顶产生的强制动作不计 log-probability。

训练采样：模式按完整 categorical；文本使用 temperature=0.7、top_p=1，避免第一版截断采样带来的概率实现歧义。重放 log-probability 使用与采样完全相同的温度和掩码。保存离散动作及 token 后以当前尚未更新的参数重算 Z、主干表示与概率；不得 detach Z 后声称训练到了循环网络。完成反传后才 optimizer.step，并重新采样下一批。

## 5. 最少需要哪些基线

### 5.1 同架构策略比较：确定收益是否来自决策

首先固定一个已训练执行器，保持主干、更新块、写回和数据完全一致，只替换策略：

| 编号 | 方法 | 排除的替代解释 |
|---|---|---|
| P0 | 只显式 E，最后 A | 新模块是否提供显式路径之外的收益 |
| P1 | 固定 K={1,2,4,8,16} 次 L 后 A | 动态优于调好 K 的固定隐式计算吗 |
| P2 | 验证集调好的周期 L/E 策略 | 优势是否只是混合两种模式 |
| P3 | 匹配平均 L/E 次数和总成本的随机策略 | 优势是否来自预算或随机性 |
| P4 | 熵／熵趋势阈值，读写执行器相同 | 状态特征是否比低成本代理更有效 |
| P5 | 状态相关 RL 策略 | 基础完整策略 |
| P6 | 动作收益监督预热＋RL | 所建议的策略增强是否必要 |
| P7 | 仅诊断的分支 rollout 策略 | 当前执行器的可利用上限，不是部署基线 |

固定同一个执行器做 P0–P7 是受控实验，但可能偏向它训练时常用的策略。因此正结果后，再分别训练最强固定／熵策略执行器，在相同训练计算预算下复核；这组是系统能力比较。

### 5.2 架构比较

- A0 共同 S0 显式 CoT：给与完整方法同量的后续 SFT/RL 训练预算，不能仅拿未经追加训练的 S0 作最终最强基线。
- A1 参数量近似匹配的一次性残差适配模块；同时报告 FLOPs，不声称参数匹配即计算匹配。
- A2 无持久状态：每次返回显式计算后重置 Z；其他预算匹配，检查工作记忆是否必要。
- A3 固定循环同模块：验证动态策略收益。
- A4 同策略输入和训练，但执行器换成主干最后两层共享循环：检验小模块是否只是弱化版循环主干。
- A5 完整模型。

不要仅把同一个模块移到 Python 类外部就称为“外部控制器基线”；如果计算图和训练信号相同，代码位置不构成科学差异。

### 5.3 相关方法比较

优先复现或在统一 backbone 上移植：SIM-CoT＋Coconut/CODI、Think-at-Hard、Learning When to Stop、SWITCH。后两者直接检验可学习停止与混合切换。SwiReasoning/SeLaR 是 training-free 参照，不替代同训练预算的主基线。HRPO 与 HALO 纳入机制比较，有资源再完整复现；HALO 的来源页面本轮未确认可运行的作者代码。

使用作者原配置跑通称“复现”；更换 backbone、数据或预算的实现称“统一条件重实现”。不能把论文原表与本实验分数直接作公平对比，也不能将 P4 的熵策略叫完整 SwiReasoning 复现。

## 6. 三阶段训练的消融与预算公平

| 编号 | 流程 | 要回答的问题 |
|---|---|---|
| T0 | 从共同起点直接联合训练 | 阶段预热是否有帮助 |
| T1 | 训练新模块→直接联合 | 单独训练主干阶段是否必要 |
| T2 | 新模块→主干→联合 | 用户提出的完整流程 |
| T3 | 短周期轮流更新→联合 | 长阶段还是短交替更稳定 |
| T4 | 只训练新模块，主干始终冻结 | 主干适应是否必要 |

关键比较 T1 vs T2。两者接触同样的数据、监督类型和初始模型；把 T2 阶段 2 用去的训练 FLOPs补给 T1 的联合阶段。还需报告总 GPU 时间、辅助解码器、分支标注和 RL rollout 的开销。仅比较相同 optimizer step 数不公平。

先做 T1/T2/T4，只有出现阶段差异再补 T0/T3，控制实验总量。首轮不能同时把训练顺序、模型大小、数据增强和模块位置全改掉。

监督消融：无步骤监督；有步骤监督；步骤标签打乱（辅助 loss 规模保持可比）；只对前期施加；全程保留。打乱标签用于机制诊断，不作为强任务基线。

策略消融：无预算输入；无历史变化特征；无动作收益预热；加入熵；只用熵和预算。训练塌缩用“条件下不恰当放弃有收益动作”定义，不能以动作不均匀直接判定。

## 7. 最重要的诊断：模型是否知道下一步值得做什么

### 7.1 相同状态的三个分支

从固定执行器的训练前缀采集 512 状态供预热；验证集独立采集 256 状态供诊断。每个状态完整保存实际 token 前缀、Z、缓存、剩余预算和 RNG。

分别强制一次 L、E、A，然后用同一参考续写策略运行到答案或预算。每个分支预热 2 次，验证诊断 4 次；模糊样本在预先规定的上限内增至 16 次，报告采样不确定性。分支都从相同起始总预算出发，L/E 消耗后只剩余扣除后的预算；不能额外赠送推理次数。

Q_hat(s,a)=mean[correct−λ·C_remaining/C_ref | 从 s 强制 a 后使用固定续写策略]。

这里估计的是该续写策略下的动作价值，不是全局最优 Q。不能用训练集预热的 Q 标签在同一状态上报告泛化。正式诊断用与预热独立的状态和 rollout 样本，避免最大值选择的乐观偏差。

观察：在相同熵、近似相同预算／步骤数分层内，最优动作是否仍随状态改变；状态模型能否比“熵＋预算”预测更低的选择遗憾。报告动作选择 regret、价值预测误差、校准、置信区间；熵与收益的相关性单独不足以证明控制能力。

如果额外计算只在少数题有效，但控制器找不到：这是策略瓶颈。如果连高成本分支诊断都没有收益：先改执行器和监督，不继续堆策略优化。

### 7.2 状态干预

- 删除第 k 次更新但执行同成本的空计算，观察答案变化；特别检查 k≥2，防止收益全部集中在第一次更新。
- 将 Z 替换成同长度、同难度的另一道题的状态，与同分布匹配对照比较。
- 受控程序中构造仅一个中间变量不同的配对题，置换对应阶段的完整状态，检验输出是否朝预期变量结果移动。
- 替换成范数匹配噪声，作为强扰动对照；其性能下降本身不证明语义推理，因为也可能是分布外扰动。
- 回滚 Z 到前一轮，观察再次更新是否恢复相关中间结果。
- 只读辅助 decoder 重建与最终答案要同时报告；可重建不等于被使用。

### 7.3 决策干预

在相似长度与成本范围内交换不同题的动作日程，或在每题内打乱 L/E 时机，保持可执行性、预算和停止约束。比较完整策略和打乱策略；动作无效时跳过并记录，不能悄悄改变预算。

问题难度与循环次数的相关性仅是描述。完整策略优于成本匹配干预，并在独立分支诊断上选出更有价值的动作，才更支持“学到了状态相关计算分配”。

## 8. 指标、统计与结果表

主指标：最终答案 exact match／程序精确正确率、完整推理 FLOPs、端到端延迟。答案解析使用 Decimal/Fraction 或规范化数值，不执行模型输出代码；解析失败计错误，不能删除失败样本。

同时报告：prefill 与 decode 时间、p50/p95 延迟、batch=1 和 batch=8 吞吐、峰值显存、实际生成 token、L/E 次数、预算强制停止率、每次循环的性能变化、训练 GPU 小时、总可训练参数和总参数。

延迟在同一设备、dtype、实现与上下文分布下测量；CUDA 同步，20 次预热，固定子集每题 5 次，采用相同解码输出或记录输出长度差异。动态分支在 batch 场景可能因填充／分歧而更慢，FLOPs 少不能直接说更快。

预算：验证上扫固定 K 和 λ，再冻结设置。主图 accuracy–FLOPs，副图 accuracy–latency；选成本接近（建议 ±5%）的真实运行点直接比较。没有匹配点就保留前沿曲线，不伪造精确同预算；延迟不按 token 数线性外推。

准确率主表采用统一 greedy 解码与确定模式选择；另报 temperature=0.7 的 pass@1 多次采样结果，以排除解码方式影响。原方法若有特定推理要求，再附作者设置表，不混进统一表。

训练种子 42/43/44。验证通过后才开最终测试；报告三种子均值、标准差及按题配对 bootstrap 的差值 95% CI。共享原题的样本按原题聚类 bootstrap；种子间波动与按题不确定性分开报。必要时报告 McNemar 检验。多次挑配置使用验证集，最终测试不反复择优。

建议主结果表字段：method、backbone_revision、train_seed、dataset、accuracy、total_flops、latency_p50_ms、latency_p95_ms、visible_tokens、latent_steps、forced_answer_rate、peak_memory、train_gpu_hours、train_total_flops。

日志每次动作保存：question_id、阶段、token_offset、latent_count、remaining_budget、action_probs、action、step_cost、state_delta_norm、最终答案、correct；可另存少量匿名化状态用于干预，不需要所有题都保存巨大 hidden tensors。

## 9. 执行顺序与停止条件

### P0 工程检查

使用 32 个合成样本做可过拟合检查，先验证三阶段的可训练参数集合、梯度到达、模块写回影响、单次 L 不增长文本位置、训练重放概率一致、没有未来步骤泄露。再用 100 个训练更新做速度／显存 profiling，据实决定 microbatch、序列上限和实验预算。

目标是暴露结构和梯度错误，不用这 32 例的准确率宣传方法。微型任务可以过拟合但泛化失败，不等于实现正确性之外的成功。

### P1 先证明执行器有效

合成线单种子：S0、一次性适配、固定 K、带步骤监督固定 K、完整三阶段固定 K。若连续增加 K 不带来任何收益，且替换／删除后续状态没有影响，先排查状态更新与监督，不启动大规模 RL。

### P2 再证明动态决策值得做

用最佳执行器做独立分支诊断。预注册继续投入标准建议：分支诊断相对最强静态策略有至少 3 个百分点的准确率潜在空间，或相当准确率下至少 15% FLOPs 空间，同时不确定性足以排除几乎无收益。这是项目资源决策阈值，不是学术显著性的通用标准；4 次分支续写不足时先增加诊断采样。

### P3 验证三阶段与策略

完成 T1/T2/T4 和 P1/P3/P4/P5/P6 的必要组合，避免完整笛卡尔积。默认先单种子筛选，保留最有解释力的 4–6 组做 3 种子。若阶段 2 无稳定收益，论文不把它列为必要贡献，即使用户最初提出该方案也应忠实报告。

### P4 真实数据与扩展

GSM8K、SVAMP 三种子复核；再扩至 1.7B 和另一个模型家族。研究价值判断的建议门槛：相同 FLOPs 下准确率提高约 2 个百分点且差值 CI 有支持，或准确率下降不超过预注册容忍值 0.5 个百分点时 FLOPs 降低至少 15%；延迟是否降低独立报告。小测试集不足以精确判断 0.5 点不劣性时，应明确统计功效不足。

满足门槛也不是顶会录用保证；未满足不能包装成显著性能进步。

暂按单张 24–48 GB CUDA GPU 作为小模型试验的资源规划范围，不承诺所有阶段都能装下。RL 轨迹顺序生成、梯度微批处理，显存以 P0 为准；冻结主干并不意味着整个训练无激活开销。没有实际硬件测量前不报价训练小时。合成、SFT、标注、RL、验证分别建立时间账单。

## 10. 创新核查：已有内容与剩余空间

### 10.1 直接近邻

| 工作 | 已经覆盖的内容 | 对当前设想的约束 |
|---|---|---|
| Universal Transformers，ICLR 2019 | 共享参数递归计算与自适应计算深度 | 循环／可学习计算深度不是新概念 |
| Recurrent Depth，NeurIPS 2025 | 循环块增加内部计算，不靠生成更多 token | 不增长文本的隐式循环不是独立首创点 |
| HRPO，NeurIPS 2025 | 门控混合连续表示与离散 token，并通过 RL 优化 | 可训练门控＋隐式／显式混合＋RL 已存在 |
| SIM-CoT，ICLR 2026 | 用训练期辅助解码器做隐状态逐步监督 | 步骤监督与推理期移除辅助模块属借鉴 |
| SwiReasoning，ICLR 2026 | 熵趋势引导显式／隐式切换 | 是规则策略参照，不是唯一对手 |
| Think-at-Hard，ICML 2026 | 小型 neural decider 选择是否进行额外隐式迭代，配合深度相关适配 | “小网络决定何时多想一步”已有正式顶会近邻 |
| Learning When to Stop，预印本 | 二分类停止头与 SFT 后 RL 优化隐式长度 | 学习停止与精度／成本奖励不新 |
| SWITCH，预印本 | 学习进入／退出隐式块，RL 梯度穿过隐状态递归，并做机制分析 | 可学习切换、端到端训练、一般状态干预都不能单独宣称首次 |
| HALO，预印本 | 冻结主干上训练轻量 refinement/controller，含 latent scratchpad 和选择性更新 | 连“带工作状态的内嵌轻量更新模块”也存在很近的设计 |
| Rational Metareasoning；约束计算分配等 | 依据计算价值优化准确率与成本 | “预测计算收益”本身也是已有研究思想 |

Think-at-Hard 应以 ICML 2026 正式版标题与结果为准，不混用较早 workshop／arXiv 版本数值。HALO 本轮按 arXiv 页面识别，未确认正式录用；页面日期字段存在不一致，不以月份建立优先权判断。

### 10.2 当前最有希望的研究角度

推荐主线是“持续的内部工作状态＋跨计算模式的动作价值学习＋同状态干预验证”。具体可检验差别是：同一状态下比较一步局部 Latent、一个 Explicit 片段和 Answer，在相同剩余预算下学习三者的相对收益；逐步监督负责状态质量，收益监督／RL 负责调用策略，并验证两类信号缺一时各自发生什么失败。

这是一项更窄的候选贡献，不是已经确认无人做过的机制。HALO 已有 learned-gain 选择，TaH 已有对困难 token 的迭代判断，SWITCH 已有混合切换与干预；论文必须逐项说明动作定义、状态持续性、真实成本、训练信号与泛化证据的具体差别。

可形成的贡献强度：

- 弱：把 MLP 放进 Block、接一个停止头、采用 SIM-CoT 或 RL、把训练分成三阶段。
- 条件性中等：在多模型上证实三阶段能解决可度量的表示不适配，并在等训练成本下稳定改善；或轻量局部循环在真实延迟上优于主干循环。
- 更值得争取：发现并证实“状态置信度与不同计算动作收益不一致”的具体失败模式；提出针对该模式的可学习机制；在同预算、跨任务／预算条件下改善前沿，并通过状态与决策干预解释收益。

不能提前将该失败模式写成所有已有方法共同瓶颈。需要先在至少两类近邻上测量，并明确其适用任务和模型。

### 10.3 可写与不可写的论文表述

未实验前可写：“我们研究通过内嵌有状态模块，联合学习隐表示更新与计算动作选择的可行性，并检验分阶段适应能否提升准确率—成本折中。”

有证据后才可写：“在模型 M、任务 D 与预算 B 的范围内，所提方法相对基线 X/Y 改善了……，状态／决策干预支持收益来自……。”

不可预先写：“首次让 Transformer 自主思考”“首次把推理模块加入 Transformer”“RL 解决模式坍缩”“逐步可解码证明真实推理”“不生成 token 因此没有计算成本”“三阶段必然优于联合训练”。
